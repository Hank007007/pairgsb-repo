# Range 处理规范

本文件规定 rangecarve 如何解释客户端发来的 `Range` 请求头。所有条款描述的是对外
可见的行为，实现方式不在本文件的讨论范围内。

## §1 适用前提

§1.1 `Range` 只对 `GET` 生效。其它方法上的 `Range` 一律忽略。

§1.2 `Range` 的值与对象长度 `size` 一起决定结果。`size` 是上游对象当前版本的
字节数，恒为非负整数。

## §2 语法与语义

### §2.1 形式与段数

`Range` 的通用形式是 `bytes=<range-set>`，其中 `<range-set>` 是若干段用 `,`
连接。单位不是 `bytes` 的（大小写不敏感地比较）整条忽略。

`<range-set>` 中最多允许 4 段。段数超过 4 时，整条 `Range` 被忽略，按没有
`Range` 处理，响应为 `200` 全量。不允许「只取前 4 段」这种部分采纳。

每一段是下面三种形式之一：

- `first-last`：闭区间，`first` 与 `last` 都是非负整数；
- `first-`从 `first` 到对象末尾；
- `-suffix`：对象末尾的 `suffix` 个字节。

空段、缺少数字的段（例如 `bytes=abc-def`、`bytes=1-2,`）使整条 `Range`
非法。非法与「超过 4 段」不是一回事：超过 4 段按忽略处理，响应 `200` 全量；
非法则整条拒绝，响应 `400 Bad Request`，不带 body。两种情况都不允许跳过坏段
继续使用好段。

### §2.2 可满足性

一段是「可满足」的，当且仅当：

- `first-last` 中 `first <= last` 且 `first < size`；
- `first-` 中 `first < size`；
- `-suffix` 中 `suffix > 0`。

只要段集合里存在一段不可满足，整条 `Range` 即为不可满足，按 §2.3 处理，
不允许丢弃坏段后返回剩余段。

### §2.3 不可满足

下列情况都算不可满足，响应为 `416 Range Not Satisfiable`，并带上
`Content-Range: bytes */<size>` 与空 body：

- 起止倒挂，例如 `bytes=5-3`；
- 后缀长度为 0 或语法上为负，例如 `bytes=-0`；
- 起点不小于对象长度，例如 1000 字节的对象收到 `bytes=9999-` 或
  `bytes=1000-1005`。

### §2.4 端点归一

对上文判定为可满足的段，按下面规则把端点收拢到对象范围内：

- `last` 大于 `size-1` 时夹到 `size-1`；
- `first-` 的终点取 `size-1`；
- `-suffix` 中 `suffix` 大于 `size` 时，起点取 `0`。

归一之后每个段都是个闭区间 `[start, end]`，满足
`0 <= start <= end <= size-1`。归一之后的段长度是 `end-start+1`。

例：1000 字节对象上 `bytes=-10` 得到 `[990, 999]`；`bytes=0-99999` 得到
`[0, 999]`。

## §3 与响应形态的关系

§3.1 段集合为空（没有 `Range` 或被忽略）时按全量 `200` 响应；整条非法按
`400` 响应，见 §2.1。

§3.2 段集合只有一段时按 `206` 单段响应。

§3.3 段集合有多段时按 `206` 多段响应，格式见 `response.md` §3。
