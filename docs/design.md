# 设计说明

## 目标

`credlint` 在推代码之前做一次凭据扫描。输入是目录或 unified diff，输出是一份可以直接贴进工单、也可以喂给 CI 的报告。设计上有两条不可让步的约束：

1. 报告里的凭据必须是残缺的，任何人拿到报告都拿不到可用的密钥。
2. 扫描必须能在大型仓库上跑完——跳过无关目录、跳过二进制、不把大文件读进内存。

## 处理流程

```
输入（目录 / diff）
  → 枚举候选文件（walker / diff）
  → 按行切分
  → 规则表匹配（rules）
  → 熵判定（entropy，仅对开启该选项的规则）
  → 单层解码后重扫（decode）
  → allowlist 过滤（ignorefile）
  → 打码（redact）
  → 报告（report）
```

## 模块职责

### `credlint/walker.py`

负责"哪些文件参与扫描"。输入根目录，产出文件路径；顺序必须稳定。三条排除规则：版本控制目录、依赖目录、二进制文件。大小上限在读取之前生效，超限文件既不读入也不扫描。

`read_text` 是唯一的读取入口，扫描器不直接 `open`。

### `credlint/rules.py`

把 `rules/*.json` 编译成规则列表。规则是数据不是代码，安全团队改表不用改 Python。每条规则声明捕获组编号，扫描器只关心那个组；`entropy` 字段决定是否追加熵判定。

### `credlint/entropy.py`

熵值是对随机性的度量，用来在宽泛的规则（例如"名字像凭据的赋值"）上压掉误报。判定对象是取值本身。随机串越长，观测到的字符分布越接近均匀分布，因此长度必须参与阈值；长度过短时样本不足，结论不可信，不应当作依据。

`shannon` 是纯函数：输入文本，输出一个可与 `MIN_ENTROPY` 比较的分数。

### `credlint/decode.py`

配配置文件里常见"整段内容是 base64"的情况。解码只做一层：解出来还是编码内容的情况留给人工。两种字母表都要接受；解出来不可读时保留原文，不要让二进制进入规则引擎。

### `credlint/ignorefile.py`

allowlist 是"已知安全的路径"清单，不是正则清单。模式按路径段解释：`*` 是单段通配，其余字符按字面处理。这样可以避免 `vendor/*` 意外覆盖整棵子树，也避免用户为了写一个点号而学正则转义。

### `credlint/diff.py`

CI 只需要看新增行。解析器跟踪当前文件与 hunk 的行号，只把 `+` 行交给扫描器，并带上新文件行号与路径。

### `credlint/scanner.py`

把上述组件串起来。`Finding` 是唯一的输出结构：

| 字段 | 含义 |
|---|---|
| `path` | 相对扫描根的路径 |
| `line` | 行号（diff 模式下为新文件行号） |
| `rule_id` | 命中的规则 |
| `preview` | 打码后的值 |
| `entropy` | 熵值，便于排序 |
| `context` | 命中行（同样经过打码） |
| `source` | `file` / `diff` / `decoded` |

`Finding` 是报告层与扫描层之间唯一的数据契约：结构里只承载展示所需的信息，下游拿到的对象可以直接序列化。

### `credlint/report.py`

文本报告面向人：路径、行号、规则打码值、行上下文。JSON 报告面向工具：`{"findings": [...]}`。两种格式共用同一批 `Finding`。

### `credlint/redact.py`

打码逻辑集中在一处，报告和日志管道都复用它。业务方会把 `redact_text` / `redact_url` 包进自己的日志中间件，因此这两个函数必须自包含、无副作用、不依赖扫描上下文。

`redact_url` 需要理解 URL 结构：path 段和 query 参数是两类不同的位置，凭据都可能出现。query 参数的敏感性由参数名判断，改名后的参数不应影响其余部分的输出。

## 错误处理

- 读不到的文件跳过并继续，不中断整次扫描。
- allowlist 文件不存在时视为空表。
- 规则表格式错误直接报错退出——规则是可信输入，静默忽略会让扫描形同虚设。
- 报告格式只接受 `text` 与 `json`，其余报错。

## 扩展点

- 新增规则：编辑 `rules/default.json` 或用 `--rules` 指定。
- 新增语言支持：规则本身与语言无关，按语法特征写即可。
- 接入 CI：`--format json --fail-on-findings`。
