# Pattern Policy — 租户正则订阅预算层

本文是预算层的规范性文件。实现必须与本文一致；本文不描述实现方式。

术语「pattern」指租户提交的正则字符串，按 UTF-8 Python `str` 处理。

## §1 受理范围

预算层只受理**子集**内的正则语法。子集之外的一律在 `check()` 阶段拒绝，不得进入编译与检索。

### §1.1 允许的语法

- 字面字符与转义字面量：`\xHH`、`\uHHHH`、`\UHHHHHHHH` 以及 Python 文档列出的字符转义（`\n`、`\t`、`\\`、`\.` 等）。
- 字符类：`[...]`，含范围、取反 `[^...]`，以及类内转义。
- 预定义字符类：`\d`、`\D`、`\s`、`\S`、`\w`、`\W`。
- 锚点：`^`、`$`、`\A`、`\Z`、`\b`、`\B`。
- 点号 `.`。
- 量词：`*`、`+`、`?`、`{m}`、`{m,}`、`{m,n}`，以及它们的非贪婪形式（后缀 `?`）。
- 分组：捕获组 `(...)`、非捕获组 `(?:...)`、命名捕获组 `(?P<name>...)`。
- 交替：`|`。
- 内联 flag 组：`(?imsx)`、`(?imsx-imsx)`、`(?imsx:...)`、`(?imsx-imsx:...)`。

### §1.2 明确不允许的语法

| 构造 | 示例 |
|---|---|
| 反向引用（数字或命名） | `\1`、`(?P=name)` |
| 前向断言 lookahead | `(?=...)`、`(?!...)` |
| 后向断言 lookbehind | `(?<=...)`、`(?<!...)` |
| 条件分组 | `(?(id)yes\|no)` |
| 原子组 / 占有量词 | `(?>...)`、`a*+`、`a?+` |
| 其他扩展 | `(?#...)`、`(?aiLmsux)` 之外的任何 `(?...)` |

上述构造返回 `ErrorCode.UNSUPPORTED_SYNTAX`，同一错误码在 `check()` 的 `detail` 中给出首个违规构造的位置。

### §1.3 畸形语法

无法解析的 pattern（括号不配对、量词无对象、转义不完整、非法 flag 组合等）返回 `ErrorCode.INVALID_SYNTAX`。

`UNSUPPORTED_SYNTAX` 与 `INVALID_SYNTAX` 必须区分：前者是「语法合法但不在子集内」，后者是「根本不是合法正则」。

## §2 归一化与长度上限

### §2.1 归一化顺序

一个 pattern 在评估长度之前，必须按以下顺序完成归一化：

1. 转义解码：`\xHH`、`\uHHHH`、`\UHHHHHHHH`、`\N{NAME}` 解码为对应字符。解码仅针对**字面量位置**的转义；`\d`、`\w`、`\b` 具有语义的转义保持原样。
2. Unicode NFKC 归一化：对解码后的整个 pattern 执行 `unicodedata.normalize("NFKC", ...)`。
3. 大小写折叠：若 pattern 携带 `IGNORECASE`，对字面量位置执行大小写折叠（`str.casefold`）。

归一化不改变匹配语义：归一化后的 pattern 与原 pattern 必须匹配同一集合（在 §3 判定的复杂度上限内）。

### §2.2 长度上限

归一化之后的 pattern 长度不得超过 **512** 个字符（Python `len()`，即码点计数）。

超过返回 `ErrorCode.PATTERN_TOO_LONG`。

长度判定必须发生在 §2.1 全部步骤完成之后。原始输入短、归一化后超限的情况同样必须拒绝。

## §3 复杂度评估

### §3.1 评估目标

评估 pattern 是否可能对某个输入产生**超线性**回溯。评估必须基于语法树，而不是字符串形态匹配。

### §3.2 嵌套重复深度

定义「重复节点」为带 `*`、`+`、`{m,n}`（`n` 无上界或 `n >= 2`）的量词节点。

**嵌套重复深度**定义为：从根到叶的最长路径上，处于嵌套关系中的重复节点数。

- 深度 ≥ 2 视为高风险。例如 `(a+)+`、`(\w+\s?)+`、`(?:[a-z]+)*`。
- 深度为 1 且无交替重叠时为可接受。

### §3.3 交替分支可重叠

对每个交替节点，若存在两个分支，其**首字符集合**（经过字符类展开与大小写折叠后）有交集，则称该交替「可重叠」。

- 可重叠交替本身不构成风险，但与重复节点组合时构成风险：`(a|a)+`、`(?:ab|a)*`、`([a-z]+|\d+)*`（两个分支的首字符集合均含数字/字母，且内部还有重复）。
- 可重叠交替位于重复节点内部时，风险等级按嵌套重复深度加一计。

### §3.4 判定

满足下列任一条件，判定为高风险，返回 `ErrorCode.REPETITION_RISK`：

1. 嵌套重复深度 ≥ 2；
2. 重复节点内部存在可重叠交替；
3. 量词的重复次数上限乘积（沿根到叶路径相乘）≥ 2^16。

`REPETITION_RISK` 的 `detail` 必须给出违规节点的位置与判定依据（深度 / 重叠分支 / 次数乘积）。

### §3.5 附录：已知灾难形态

下表是回归参照。每一行在 `check()` 阶段都必须返回 `REPETITION_RISK`，且不得进入编译。

| # | 形态 | 示例 |
|---|---|---|
| R1 | 单层重复内含重复 | `(a+)+$` |
| R2 | 重复内含空白可选字符类 | `(\w+\s?)+$` |
| R3 | 单字符可重叠交替重复 | `(a\|a)+$` |
| R4 | 字符类交替重复 | `([a-z]+\|\d+)*$` |
| R5 | 预定义类交替重复 | `(?:\d+\|\w+)+$` |
| R6 | 非捕获组嵌套重复 | `(?:a+)+$` |
| R7 | 空分支重复 | `(a*)*$` |
| R8 | 多字符重叠交替 | `(?:a\|a)*$` |

## §4 匹配预算与中止

### §4.1 单次请求预算

一次 `search_all` 调用是**一个请求**。请求的总匹配时间预算为 **200ms**，覆盖该请求内所有字段、所有匹配位置。

预算按请求计，不按字段计：字段数增加不得线性放大预算。

### §4.2 超预算处理

- 预算耗尽时，`search_all` 必须中止匹配，返回 `SearchOutcome.TIMEOUT`，并携带已完成的匹配结果（按字段分组、按出现顺序）。
- 中止必须实际打断正则引擎的回溯，而不是在匹配结束后再比较耗时。
- 中止后进程必须仍然可用：不得阻塞调用线程超过预算（加上固定的调度余量）。

### §4.3 观察名单

任何一次 `SearchOutcome.TIMEOUT` 都会把该 pattern（连同 flags）记入观察名单 `Watchlist`。

- 观察名单以 pattern 与 flags 的规范化组合为键。
- 命中观察名单的 pattern 在后续 `check()` 中返回 `ErrorCode.WATCHLISTED`。

## §5 编译缓存

### §5.1 缓存键

编译缓存的键必须包含 **pattern 归一化字符串** 与 **生效 flags**。两者任一不同即视为不同条目。

- flags 包含：调用方传入的 flags、pattern 内联 flag 组声明的 flags、以及默认 flags。
- 不同 flags 的同一 pattern 不得共用编译结果。

### §5.2 失效

缓存容量上限 256 条，超出时按最近最少使用淘汰。观察名单变更不影响缓存内容。

## §6 错误码

`ErrorCode` 枚举中已定义的取值不得删除或改名。允许增加新值。

| 取值 | 含义 |
|---|---|
| `OK` | 通过 |
| `PATTERN_TOO_LONG` | §2.2 超长 |
| `UNSUPPORTED_SYNTAX` | §1.2 子集外构造 |
| `INVALID_SYNTAX` | §1.3 畸形语法 |
| `REPETITION_RISK` | §3.4 复杂度高风险 |
| `WATCHLISTED` | §4.3 观察名单命中 |

错误码必须具体：不得用 `INVALID_SYNTAX` 兜底 §1.2 或 §3.4 的判定。

## §7 检索语义

### §7.1 结果形态

`search_all(pattern, fields)` 对每个字段返回该 pattern 的所有**非重叠**匹配，顺序为字段顺序 × `finditer` 顺序。字段为空或 pattern 未命中时，结果为空列表。

### §7.2 flags 语义

`IGNORECASE`、`DOTALL`、`MULTILINE` 按 Python `re` 语义生效。内联 flag 组与调用方 flags 合并；内联组内的 `-i` 等形式按 `re` 语义覆盖。

### §7.3 正常路径

正常 pattern 在预算内的匹配结果必须与不使用预算层直接 `re.finditer` 的结果逐条一致（相同的 `start`/`end`/`group`）。
