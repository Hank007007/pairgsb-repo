# 提权规则

本文档定义 `glassbreak` 在语义上必须满足的行为。它只描述「什么算对」，不规定代码如何组织。
当实现与本文冲突时，以本文为准。

## §1 术语

- **申请人（subject）**：发起提权申请的操作者，必须属于 `policy/groups.yaml` 中某个组。
- **基础 scope**：申请人所在组在 `base_scopes` 中列出的权限，申请人平时即持有。
- **追加 scope（requested）**：申请中写明、希望在基础 scope 之上额外获得的权限。
- **可提权集合（grantable）**：`grantable.yaml` 中 `grantable` 列出的 scope，代表本次提权允许触及的
  范围上限。
- **审批人（approver）**：对某份申请投出同意票的组成员。
- **审批窗口**：申请提交后可以被批准的时长，取 `policy/groups.yaml` 的 `approval_window_minutes`。
- **max_ttl**：凭据有效期的上限，取 `grantable.yaml` 的 `max_ttl_minutes`。

## §2 scope 规划

§2.1 申请生效的 scope 是「基础 scope」与「追加 scope」的并集，且追加部分必须先受可提权集合约束。

§2.2 最终 scope 中出现的每一个非基础项，都必须同时满足：出现在申请中，且出现在可提权集合中。
不在可提权集合中的追加项不得进入最终 scope，无论其形式是否看起来像通配符或上游是否接受。

§2.3 基础 scope 不受可提权集合限制：它本来就属于申请人，提权不改变它的存在。

§2.4 通配符（例如 `iam:*`）只有在可提权集合中逐字列出时才可生效；不能因为「看起来能覆盖已有条目」
而被接受。

## §3 投票资格

一次投票只有同时满足以下全部条件才应当被计入：

§3.1 **非本人**：投票人不是申请人本人。

§3.2 **同组**：投票人与申请人属于同一个组。跨组成员投出的同意票不计入票数。

§3.3 **非被点名者**：申请人在申请中指定了 `named_approver` 时，该被指定的个人不得为这份申请投票。
这一条用于阻止申请人与某个审批人预先串通。其余同组成员不受影响。

§3.4 不满足 §3.1–§3.3 的投票必须被拒绝：它既不能增加票数，也不能把申请推进到已批准状态。
拒绝的方式（抛错、返回错误结果）由实现决定，但状态不得因此改变。

## §4 计票

§4.1 每份申请需要 `required_votes` 张**有效且互不相同**的审批人投出的同意票，票数门槛取自申请人
所在组。

§4.2 同一个审批人对同一份申请多次投票，只算一票。重复投票不得累加，也不得使申请提前达到门槛。

§4.3 达到门槛的那一刻申请进入已批准状态，并记录批准时刻与该时刻生效的 scope 快照。

§4.4 票数门槛按「不同审批人的人数」计算，不按「投票动作的次数」计算。

## §5 审批窗口

§5.1 申请提交后，在审批窗口内（`created_at` 起算，长度等于 `approval_window_minutes`）没有被批准，
即视为过期。

§5.2 过期申请不得再被批准，也不得签发凭据；对其投票或索取凭据应当被拒绝。

§5.3 已经过期的申请不会因为收到新投票而复活。

§5.4 窗口边界的取舍：恰好在窗口结束时刻收到的投票是否有效，以实现中窗口比较的边界约定为准，
但同一约定必须同时应用于投票与签发两条路径。

## §6 凭据

§6.1 **TTL**：凭据有效期等于「申请时长」与 `max_ttl` 中的较小值。申请超过上限时，凭据按上限签发，
申请中写的时长不应被无条件照搬。

§6.2 **起算点**：有效从**审批通过的时刻**开始计算，而不是从申请提交的时刻。审批耗时不计入凭据寿命。

§6.3 **scope 来源**：凭据携带的 scope 取自批准时记录的 scope 快照（即 §2 规则下当时生效的那份），
而不是重新按请求内容推导，也不是申请提交时的原始请求。

§6.4 **唯一性**：一份申请最多签发一张凭据。对同一申请重复请求签发，必须返回此前已签发的那张凭据
（同一个 `credential_id`、同样的 scope 与同样的到期时间），不得产生新凭据，也不得借此延长期限。

§6.5 **前置条件**：只有处于已批准且凭据未签发状态的申请可以签发凭据。未达票数、已过期、或状态
不明的申请一律拒绝签发。

§6.6 **到期即失效**：凭据在其 `expires_at` 之后不再有效，无需额外的撤销动作。有效期不得被续期。

## §7 审计

§7.1 每一次申请创建、每一次投票（无论是否被计入）、每一次批准、每一次凭据签发都应当留下带时间戳、
申请人/操作者与申请标识的审计记录。

§7.2 审计记录只追加，不修改、不删除。

§7.3 审计中记录的 scope 应与实际签发的凭据一致，便于事后核对「当时到底放出去了什么」。

## §8 配置数据

§8.1 `grantable.yaml` 与 `policy/groups.yaml` 是策略数据，服务只读。

§8.2 若某个主体不属于任何组，不能提交申请，且不具备任何基础 scope。

§8.3 票数门槛、审批窗口、`max_ttl` 均从配置读取，不得在代码中写死为与配置无关的常量。
