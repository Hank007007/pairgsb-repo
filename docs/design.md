# tplsentry 设计说明

`tplsentry` 是运营平台的通知模板引擎：运营在后台编写邮件模板，系统把告警、
账单等业务数据填进去渲染成 HTML。模板来自运营后台，数据里混着用户昵称、
工单标题等内容，两者都按不可信输入对待。

边界条款见 [`docs/sandbox-rules.md`](sandbox-rules.md)。本文说明引擎的组成
与各部分的职责，以及对外承诺的行为。

## 1. 对外接口

```python
from tplsentry import TemplateLoader, render

loader = TemplateLoader("templates/")
template = loader.get_template("notice.html")
html = render(template, {"user": {"name": "Alice"}, "items": [...]})
```

- `TemplateLoader(template_dir, cache=True)`：从目录读取模板源，返回已解析的
  `Template`。`get_template` 对同名模板可复用解析结果。
- `Template(source, name="<string>")`：直接从字符串构造模板，适合单元测试与
  内联片段。
- `render(template, context, loader=None, limits=None)`：返回渲染后的字符串。
  未显式传 `loader` 时沿用模板自身的来源目录。
- `Limits`：三个资源上限，见 §4。

所有渲染期失败都抛 `TemplateError` 的子类，调用方按基类捕获即可。

## 2. 处理流程

```
模板源 ──> 词法/语法分析 ──> 节点树 ──> 逐节点求值 ──> 转义 ──> 输出
                │                            │
                └── 表达式节点               └── include / extends 时递归进入
                    （变量、属性、过滤器）        被引用模板
```

三个阶段边界清晰：

1. **解析**：把模板源切成文本、输出标签、语句标签三类片段，构造不可变的
   节点树。表达式在解析期完成词法与语法分析，语法错误在这一步暴露，而不是
   等到渲染时。
2. **求值**：遍历节点树，维护一个变量作用域，产出字符串片段。
3. **输出**：每个 `{{ }}` 的求值结果在写入片段列表前统一转义。

解析与求值分离带来两个性质：模板只解析一次即可复用；语法错误与运行期错误
可以用不同异常类型区分。

## 3. 模块职责

| 模块 | 职责 |
|---|---|
| `tplsentry/parser.py` | 模板源到节点树：文本、输出、`for`、`if`、`include`、`extends`、`block` |
| `tplsentry/expr.py` | 表达式词法与语法分析，产出元组形式的表达式节点 |
| `tplsentry/render.py` | 节点遍历、作用域管理、表达式求值、include/extends 解析 |
| `tplsentry/sandbox.py` | 上下文包装与属性读取的边界 |
| `tplsentry/loader.py` | 模板名到文件路径的解析、读取与缓存 |
| `tplsentry/filters.py` | 过滤器登记表与调用 |
| `tplsentry/escape.py` | `Markup` 标记与 HTML 转义 |
| `tplsentry/limits.py` | 三个上限的默认值与容器 |
| `tplsentry/errors.py` | 异常层次 |

模块之间只通过显式参数传递数据：渲染器不持有全局状态，作用域在循环体里以
拷贝方式派生，因此一次渲染的结果不依赖此前渲染过什么。

## 4. 表达式语言

支持的最小集合，足以覆盖通知模板：

- 字面量：整数、浮点、单/双引号字符串、`true` / `false` / `none`、列表
- 变量名：从当前作用域读取
- 属性访问 `a.b`、下标 `a[b]`
- 函数调用 `a(b, c)`：仅作用于作用域中确实可调用的值，以及内置 `range`、`len`
- 过滤器 `a|filter`、`a|filter(arg)`
- 一元运算 `not`、`-`
- 二元运算：`and` `or` `==` `!=` `<` `>` `<=` `>=` `in` `not in`
  `+` `-` `*` `/` `//` `%`

表达式语言刻意保持小：没有赋值、没有 import、没有 lambda、没有属性写入。
模板作者表达的是展示逻辑，不是程序逻辑。

## 5. 作用域

- 顶层作用域即渲染调用传入的上下文。
- `{% for %}` 每次迭代从当前作用域派生一个子作用域，写入循环变量后渲染循环
  体；迭代之间互不影响。
- `{% include %}` 在被引用模板中沿用调用点的作用域。
- `{% extends %}` 先渲染父模板，父模板中同名 `block` 的内容由子模板提供。

作用域对模板而言只读。模板不能改写上下文，也不能把值从一个作用域带到另一个。

## 6. 转义模型

- 默认信任级别是"不可信"：`{{ expr }}` 的结果一律转义。
- `Markup` 是"已可信"的标记类型，引擎内部在确定内容安全时使用它。
- `|safe` 是模板作者显式声明的信任，因此只对模板里写死的字符串字面量开放；
  对变量使用等于让数据决定信任级别，必须报错。

信任判断只看值是不是由模板字面量产生，不看值被什么类型包装过。

## 7. 资源模型

一次 `render` 是一个有界操作。三个上限共同保证最坏情况可控：

| 上限 | 约束对象 | 触发后 |
|---|---|---|
| `max_loop_iterations` | 所有 `for` 的迭代总数 | 立即中断 |
| `max_output_bytes` | 输出 UTF-8 字节数 | 立即中断 |
| `max_render_seconds` | 单次 render 的墙钟时间 | 立即中断 |

上限是"边做边核"的：在循环体入口核对次数与时间，在写入输出片段时核对字节数。
事后统计无法阻止 `{% for i in range(100000000) %}` 占满 worker。

## 8. 模板解析与继承

- 模板名在 `include` / `extends` 中解析为相对模板根目录的路径。
- 解析结果必须落在根目录内，真实路径（含符号链接展开后）也必须在根目录内。
- 继承：子模板声明 `extends`，只贡献 `block` 内容；父模板决定整体骨架。
- `include` 与 `extends` 都可以嵌套。

## 9. 非目标

- 不做模板编译缓存到磁盘，不做多进程渲染。
- 不提供任意 Python 表达式求值，不支持导入模块或调用上下文以外的函数。
- 不实现自动转义豁免机制（例如上下文级别的 `safe` 标记），信任只能来自
  模板字面量或引擎内部。
- 不覆盖富文本编辑器语义；模板语言保持文本级。

## 10. 测试策略

测试覆盖引擎的正常路径：变量与嵌套映射、循环与空循环、条件分支、
`include` 页脚、默认转义与过滤器。夹具模板位于
`tests/fixtures/templates/`。

边界行为（属性访问、路径解析、资源上限、信任级别）按
[`docs/sandbox-rules.md`](sandbox-rules.md) 验收，不在本仓库的单元测试范围内。
