# StowSign 线上事件记录

本文件按时间倒序记录与预签名 URL 相关的生产事件。每条包含影响面、时间线与
复盘结论。规范条款以 `presign-spec.md` 的章节号引用。

---

## INC-2025-0417 · 前缀越界读取

**等级**：P1　**影响**：`eu-central` 桶内约 1.2 万个非授权对象被下载

**经过**：一位合作方持有前缀为 `photos` 的读授权。其客户端把请求路径改成
`photos-backup/2023.tar`，服务端返回 200。进一步探测发现 `photos.bak/`、
`photos-old/` 同样可读。这些目录与前缀目录同级，只是名字以相同字符串开头。

**复盘**：前缀授权表达的是目录边界，不是字符串相等或字符串前缀。授权
`photos` 只应覆盖 `photos` 本身与 `photos/` 之下的键（规范 §7）。把键当普通
文本做前缀比较会把同级的兄弟目录一并暴露。

**后续动作**：为受影响的合作方轮换凭据；统计口径里补上「按路径段边界匹配」
的查项。

## INC-2025-0908 · 编码变体绕过签名

**等级**：P1　**影响**：只读授权被用于写入对象

**经过**：攻击者拿到一条 `GET` 预签名 URL，把请求行里 `X-Stow-Resource` 的值
从 `photos%2Fcat.jpg` 改成 `photos%2F..%2Fadmin%2Fconfig`，同时把另一些参数
的 `%20` 直接换成空格。服务端校验通过。事后确认，把 `%2F` 换成 `/`、把
`%41` 换成 `A` 等「等价但写法不同」的变体同样能通过。

**复盘**：签名覆盖的必须是线上字节，而不是某种解码后的中间表示。`%2F` 与
`/` 在路径语义上不同，在签名语义上更必须不同（规范 §2）。任何在拼签名串之前
做的解码，都会把「改编码」变成「改内容」的免费通道。

同一次事件中还发现：把查询参数整体重排后，签名同样不变。规范要求规范查询串
按编码后的键排序（规范 §3），因此重排后签名本应仍然一致——但当时实现依赖的是
接收顺序，说明签发端与校验端对「规范形式」的认定并不一致，两端只是碰巧在同一种
顺序下才互认。

## INC-2025-1126 · 签名 header 只校验存在性

**等级**：P1　**影响**：上传内容类型与内容摘要可被替换

**经过**：一条签了 `Content-Type: image/png` 与 `Content-MD5` 的写入 URL 被
转卖。买方把 `Content-Type` 改成 `text/html`、`Content-MD5` 改成另一个值，上传
成功。桶上配置了按 `Content-Type` 分发的边缘缓存规则，导致 HTML 被当作图片
缓存并下发给终端用户。

**复盘**：header 进入签名的目的就是绑定值。规范 §4 要求用请求上实际携带的值
重算 header 块摘要；只确认名字存在，等于把这两个 header 降级成装饰。凡是进入
`X-Stow-SignedHeaders` 的名字，其值都必须参与重算。

## INC-2026-0109 · 有效期被解释成相对时间

**等级**：P2　**影响**：一批 1 小时授权在数月内持续可用

**经过**：安全团队在季度扫描中发现，2025 年 10 月签发的若干 URL 到 2026 年 1 月
仍能通过校验。抓包显示客户端从未刷新签名。核对代码发现，`X-Stow-Expires`
在签发时写入 TTL 秒数，校验时被当作「从当前时刻起还能用多少秒」重新计算。

**复盘**：`X-Stow-Expires` 是绝对时刻，签发即冻结（规范 §6）。把它当相对时间，
等价于每次校验都把截止时间往后推，授权永不失效。同一时期还发现另一侧问题：
签发接口对 TTL 没有上限，某客户申请了 180 天的 URL 也被照签。规范规定单次授权
不超过 7 天，超出必须拒绝（规范 §6）。

## INC-2026-0214 · 来源限制对 IPv6 不生效

**等级**：P2　**影响**：带 CIDR 限制的策略被 IPv6 客户端整体绕过

**经过**：`us-west` 集群双栈上线后，策略中配置了 `ip_cidrs: ["10.0.0.0/8"]` 的
签发请求，从 `2001:db8::/32` 网段访问时全部放行。另有一批请求因为代理没有透传
来源地址，字段为 `null`，同样被放行。

**复盘**：来源地址比较需要同时支持 IPv4 与 IPv6（规范 §9）。解析失败或地址缺失
时按拒绝处理——当前实现把异常吞掉后当作通过，等于让「取不到地址」成为最省事的
绕过方式。IP 限制的目的就是缩小可用面，任何不确定都应落在拒绝一侧。

## INC-2026-0302 · 复制授权的目标资源未受约束

**等级**：P2　**影响**：源桶数据被写入未授权目标前缀

**经过**：某服务申请了「从 `photos` 复制到 `backup`」的授权，策略里只写了
`resources: ["photos", "backup"]`。审计时发现该凭据把源对象复制到了
`public/`，而 `public/` 并不在策略中。

**复盘**：服务端复制场景下，源与目标都是被授权的资源，两者都必须被策略覆盖
（规范 §8）。签发端在写入 `X-Stow-Target` 前应校验目标，校验端在放行前应再次
校验两端的组合。
