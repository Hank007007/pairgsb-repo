# 审计链这周的问题

> 内部群和一次外部审计里摘的，按时间倒序。

## 2026-11-14 · 外部审计机构的抽查结论

他们拿了我们的 staging 数据做了四种改动，`verify` 全报了 ok，原话是"这条链目前只能证明
文件没被截断"：

1. 挑一段里的一条记录，把 `action` 从 `read` 改成 `delete` —— ok。
   我们复现了，改完之后 `node src/cli.js verify` 退出码 0。
2. 把整条记录从 `segment-0003` 挪到 `segment-0007`，`seq` 和 `segment` 都改了 —— ok。
3. 把 `segment-0002` 整个文件换成另一份长度相同的 —— ok。
4. 往 `segment-0001` 末尾追加一条自己造的记录 —— ok。

第 4 条他们补了一句：追加的时候 `prevMac` 填的是对的，但显然这不影响结论。

## 2026-11-11 · 平台组：删了一条记录反而校验不过

跟上面那几条相反，他们把一个段的中间一条记录删掉，报的是 `chain-link`，
这个没问题。但把一个段**最后一条**删掉（连同后面那段没动）就完全没反应，ok。
他们的意思是：这跟"整段被截断"是一回事，应该报。

## 2026-11-09 · 应用安全组：manifest 被改过也照样 ok

测试环境里有人手改 `manifest.json` 里的 `prevMac`、`seq`、`count`，`verify` 仍然 ok。
`open()` 从 manifest 恢复位置这件事，我们希望它只影响"接下来写哪儿"，
不该影响"已经写下去的东西对不对"。

## 2026-11-06 · 应用安全组：一条链断了就不往下查了

一个 40 段的老日志，第 3 段出问题，`verify` 只返回到第 3 段就停了，后面 37 段的结论
完全看不到。审计要的是"影响范围"，得知道后面哪些还是好的。
