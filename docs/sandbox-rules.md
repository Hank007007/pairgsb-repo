# tplsentry 沙箱规则

本文规定 `tplsentry` 在渲染不可信模板与不可信数据时必须满足的边界。文中只描述
对外可观察的行为，不描述实现方式。凡标注"必须"的条款都是验收条件。

## §1 上下文与变量

1.1 模板只能读取渲染调用传入的上下文变量，以及引擎显式登记的少量内置名字
（`range`、`len`）。

1.2 引用一个未定义的变量必须抛出 `TemplateError`，不得静默渲染为空字符串。

1.3 上下文里的普通映射（`dict`）在模板中既可以按变量名读取，也可以按属性
读取；属性名不存在时同样必须报错。

1.4 渲染过程不得向上下文对象写入任何数据。

## §2 属性访问

2.1 表达式中以 `.` 或 `[...]` 形式出现的属性名，若以下划线开头，必须拒绝，
并以 `TemplateError`（或其子类 `TemplateSecurityError`）终止渲染。此规则
覆盖任意深度，例如 `a._b.c`、`a.__init__.__globals__`。

2.2 模板不得通过任何途径取得 Python 运行时对象：类型对象、函数、方法、
模块、帧、内建命名空间都视为越界。典型输入包括
`{{ "".__class__ }}`、`{{ "".__class__.__subclasses__() }}`、
`{{ user.__init__.__globals__ }}`。

2.3 过滤器同样构成访问途径。`attr` 过滤器传入的名字必须遵守 2.1，不得成为
绕过属性限制的第二条通道：`{{ x|attr("__class__") }}` 必须报错。

2.4 上述限制与数据来源无关：上下文变量、字面量、循环变量、过滤器返回值
都是检查对象。

## §3 模板加载

3.1 `{% include %}` 与 `{% extends %}` 的模板名只能是相对路径，解析结果必须
位于模板根目录之内。

3.2 包含 `..` 段而逃出根目录的名字必须拒绝，例如 `../secret.txt`；
`..` 段在解析后仍落在根目录内的名字可以接受。

3.3 绝对路径（POSIX 的 `/x`、Windows 的 `C:\x`、UNC 路径）必须拒绝。

3.4 校验必须作用在解析后的真实路径上：若符号链接、目录联接等机制使某个
名字最终指向根目录之外，同样必须拒绝。

3.5 越界访问必须以 `TemplateError`（推荐 `TemplateSecurityError` 或
`TemplateNotFoundError`）结束，不得把目标文件内容渲染进输出。

3.6 加载失败与越界拒绝在错误类型上可以区分，但都不得泄漏被拒绝路径的
文件内容。

## §4 资源上限

`Limits` 定义单次渲染的三个上限：`max_loop_iterations`、
`max_output_bytes`、`max_render_seconds`。任一上限被触及时，渲染必须立即
中断并抛出 `TemplateLimitError`。

4.1 循环次数：单次渲染所有 `{% for %}` 的执行次数之和不得超过
`max_loop_iterations`。`{% for i in range(100000000) %}` 这类输入必须在上限
处停止，而不是跑完。

4.2 输出字节数：渲染产物的 UTF-8 字节数不得超过 `max_output_bytes`。检查
必须在拼接过程中进行，使超出上限的模板尽早中断；不得先构造完整输出再判断。

4.3 渲染时长：从进入渲染到结束的墙钟时间不得超过 `max_render_seconds`。
检查必须发生在循环体等可重复执行的路径内，使长时间运行的模板能被打断。

4.4 三个上限对嵌套 include 与 `{% for %}` 的 `{% else %}` 分支同样生效。

## §5 转义与 safe

5.1 `{{ }}` 输出必须默认做 HTML 转义，转义应覆盖 `& < > " '`。

5.2 引擎自身产生的 `Markup` 才可信。上下文里由调用方构造的 `Markup`
包装值视同普通用户数据，必须照常转义；"被 `Markup` 包过"本身不构成信任
依据。

5.3 `|safe` 只允许作用于模板中的字符串字面量，例如
`{{ "<b>hi</b>"|safe }}`。参数为变量、属性、循环变量、函数结果或其他
表达式时，必须抛出 `TemplateError`。

5.4 `|safe` 作用于字面量时，该字面量按原样输出，不再转义。

5.5 过滤器链中，转义发生在整条表达式求值完成之后。

## §6 过滤器

6.1 已登记的过滤器：`upper`、`lower`、`trim`、`length`、`default`、`join`、
`attr`、`safe`。

6.2 未知过滤器必须抛出 `TemplateError`。

6.3 过滤器内部因类型不匹配等原因失败时，必须转换为 `TemplateError`，
不得把底层异常直接抛给调用方。

6.4 `join` 与 `length` 只接受可迭代/有长度的值，其余情况按 6.3 处理。

## §7 错误模型

7.1 所有渲染期错误都是 `TemplateError` 的实例；调用方只需要捕获这一个
基类即可区分"模板有问题"与"引擎本身崩溃"。

7.2 子类语义：

| 类型 | 含义 |
|---|---|
| `TemplateSyntaxError` | 模板无法解析 |
| `TemplateNotFoundError` | 模板不存在或不可读 |
| `TemplateSecurityError` | 试图越出 §2、§3 的边界 |
| `TemplateLimitError` | 触及 §4 的任一上限 |

7.3 错误信息可以包含变量名、模板名与上限值，不得包含被拒绝对象的内容。
