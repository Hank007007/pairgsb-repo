# X-Signature v2 规范

> 这是与对接方共同商定的线上规范，**以本文件为准**。
> 任何实现（包括本仓库的 `hooksign`）都必须按本文计算；偏差一律视为实现 bug。

## 1. 请求头

```
X-Signature: t=<unix 秒>,v1=<hex>,v1=<hex>
```

- 头名大小写不敏感（HTTP 语义）。
- 条目之间以 `,` 分隔，条目内可出现空白，解析时应去掉。
- 不认识的条目名（含 `v2`、`v0`）必须忽略，不能报错。
- `v1` 可以重复出现，语义是"签名者同时用多把候选密钥签了同一个值"，
  接收方只要**任一** `v1` 匹配即通过。
- 缺少 `t` 或没有任何非空 `v1`，视为格式错误。

## 2. 待签名字符串

按 `\n` 连接以下五行，**不额外添加**空行，结尾也不带 `\n`：

```
v2
<METHOD>
<PATH>
<timestamp>
<body_sha256_hex>
```

- `METHOD`：大写 HTTP 方法。
- `PATH`：请求路径，含查询串之外的完整路径部分（不做 URL 解码）。
- `timestamp`：头里的 `t` 值，十进制，不补零。
- `body_sha256_hex`：**原始请求体字节**（不解码、不转码、不做任何规范化）的
  SHA-256，小写十六进制。

## 3. 签名算法

```
signature = hex(HMAC-SHA256(secret_key, 待签名字符串的 UTF-8 字节))
```

比较签名时必须使用**常量时间**比较，禁止用 `==`。

## 4. 时间与重放

- 时间容差 300 秒：`|now - t| > 300` 拒绝，`reason = "timestamp_skew"`。
- 同一份签名（同一 `t` + 同一 `v1` 值）在容差窗口内**只接受一次**，
  重复投递按幂等命中处理，`reason = "replay"`。
- 注意：不同事件可能在同一秒内到达，**`t` 相同不代表是重放**。

## 5. 密钥轮换

- 密钥环中可能存在多把密钥，接收方必须**遍历所有未过期密钥**验证，
  不能只用其中一把。
- 出方向签名使用最后添加且未过期的那把。

## 6. 幂等

- `event_id` 是投递方生成的全局唯一 ID。同一个 `event_id` 重复投递只处理一次，
  第二次起返回成功但不再执行业务。
- 并发投递同一 `event_id` 时也必须只成功一次（不允许两条都执行，也不允许抛异常）。

## 7. 失败原因码

| reason | 含义 | HTTP |
|--------|------|------|
| `missing_header` | 没有 `X-Signature` | 401 |
| `malformed_header` | 头格式错误 | 400 |
| `timestamp_skew` | 时间戳超窗 | 401 |
| `bad_signature` | 名不匹配 | 401 |
| `replay` | 窗口内重复 | 200（幂等命中） |
