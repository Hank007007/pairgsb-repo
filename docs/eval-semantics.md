# 安全组求值语义

本文是 netacl 的规范性文档。它只描述**求值结果应当是什么**，不描述实现方式，也不规定内部数据结构。

控制面有两个调用方，它们问的是同一个问题：给定的源（CIDR、prefix list 或另一个安全组）能否到达目标安全组上的某个协议和端口。

- 编排器在下发规则前调用求值器，预检规则组合是否会产生非预期放行。
- drift 检测器在巡检时调用求值器，比对线上实际可达性与期望策略。

调用方依赖的是本文定义的语义，而不是某一次实现的具体行为。

---

## §1 范围

一个安全组（`SecurityGroup`）包含两组规则：ingress（入站）与 egress（出站）。每次求值必须指定：

1. 目标安全组；
2. 方向（ingress 或 egress）；
3. 报文：源地址、目的地址、源端口、目的端口、协议。

端口判定使用报文的目的端口：ingress 方向下它是对端访问本地服务的端口，egress 方向下它是本地访问远端服务的端口。

若目标安全组不存在、方向未知或协议名未知，求值返回错误。错误不得被当作放行。

## §2 规则编号与求值顺序

- 每个组的每个方向内，规则编号唯一。
- 规则按编号**数值升序**求值，而不是按字符串序、插入序或容器遍历序。
- 第一条同时匹配协议、端口和源的规则决定结果：allow 放行，deny 拒绝。其后的规则不再参与判定。
- 若没有任何规则匹配，结果为拒绝。这称为末尾隐式拒绝。
- 同一组内 allow 与 deny 可以作用于同一协议和端口；此时编号更小的那一条胜出。
- 求值结果不得依赖规则在内存中的存放顺序。相同输入、相同策略版本必须得到相同结果。

## §3 协议匹配

- 协议名使用规范小写记号：`tcp`、`udp`、`icmp`、`all`。
- 规则协议为 `all` 时匹配任意报文协议。
- 其余情况下，规则协议必须与报文协议**完全相同**才可能匹配。
- 协议不同时，即使端口和源都命中，该规则也不匹配。

## §4 端口区间

- 规则声明的是闭区间 `[FromPort, ToPort]`。
- `FromPort == ToPort` 表示只允许一个端口，而不是允许所有端口。
- 只有报文目的端口 `port` 满足 `FromPort <= port <= ToPort` 时才匹配。
- 端口小于 `FromPort` 或大于 `ToPort` 时一律不匹配；区间之外没有任何端口可以命中。
- 端口区间只对 `tcp` 和 `udp` 有意义。`icmp` 和 `all` 规则的端口字段不参与判定。

## §5 源的类型

每条规则恰有一个源，三种之一：

1. **CIDR**：单个 CIDR 块。地址落在该块内即命中。
2. **prefix list**：按名称引用一个命名前缀列表。求值时把它展开为条目集合，条目之间是并集；地址落在任意条目内即命中。展开必须使用本次求值所固定的版本（见 §9）。
3. **安全组**：见 §6。

未定义的引用（不存在的 prefix list、不存在的安全组）不覆盖任何地址。引用无法解析时规则不匹配，最终由隐式拒绝兜底，即失败关闭。

## §6 安全组引用

- 安全组引用按组标识**精确相等**解析：只包含当前成员关系中组标识与引用完全相同的实例。
- 名称前缀相同不构成同组。例如引用 `sg-web` 不得带入属于 `sg-web-admin` 的实例。
- 成员关系是动态的，以本次求值固定的版本为准（见 §9）。
- 成员地址与报文源地址的比较在按 §7 归一之后进行。

## §7 地址族与归一化

- 求值器同时支持 IPv4 与 IPv6。
- IPv4-mapped IPv6 地址（形如 `::ffff:a.b.c.d`）在参与**任何**匹配之前，必须先归一为对应的 IPv4 地址。
- 归一之后，IPv4 地址只与 IPv4 的 CIDR 比较，IPv6 地址只与 IPv6 的 CIDR 比较。
- 归一必须发生在 deny 与 allow 判定之前。同一个主机地址无论以纯 IPv4 还是 IPv4-mapped 形式出现，都必须得到相同结论，尤其不得因为表示形式而绕过显式 deny 后落入更宽松的后续 allow。
- 安全组成员地址同样适用本条。

## §8 有状态回程流量

连接表记录**发起方向**的完整五元组：

- 源地址
- 目的地址
- 源端口
- 目的端口
- 协议

一个报文属于已建立连接的回程，当且仅当以下四项**全部**成立：

1. 协议与记录相同；
2. 源地址等于记录的目的地址；
3. 目的地址等于记录的源地址；
4. 源端口等于记录的目的端口，且目的端口等于记录的源端口。

只有完整匹配的回程流量才可以跳过规则求值直接放行。仅地址相同、仅端口对调、或协议不同，都不构成回程，必须回到规则求值（从而可能被拒绝）。

由此产生两条必须同时满足的推论：

- **伪造防护**：外部主机伪造一个地址相同、端口对调的报文，不得被当作回放行。
- **策略收紧不误杀**：一条连接一旦建立，其回程流量不再重新查规则；即使随后策略收紧到不再允许该连接，已建立连接的合法回程仍应被放行，直到连接被显式移除、超时或重置。

新连接的发起方向不走连接表快捷路径，必须正常经过 §2 的规则求值。

## §9 快照一致性

- 一次求值（一次 `Evaluate` 调用）看到的组成员关系与 prefix list 必须来自**同一代版本**。
- 求值进行期间发生的成员变更、prefix list 更新或安全组替换，不得只影响该次求值的一部分：要么整次求值看到旧版本，要么整次求值看到新版本。
- 不同求值之间可以观察到不同版本；版本边界以一次求值为单位。

## §10 确定性与错误

- 相同输入、相同策略版本，重复求值必须得到相同结果。`go test -count=N` 重复运行不得出现抖动。
- 未知目标安全组、未知方向、未知协议：返回错误。
- 规则源引用无法解析：该规则不匹配（失败关闭），最终结果由隐式拒绝给出。
- 空规则簿：任何流量都被拒绝。
