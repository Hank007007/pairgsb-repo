# rangecarve 设计说明

这份文档说明 rangecarve 各层「应该做什么」，以及它们之间怎样传递信息。它只描述
可观察的行为和边界，不描述具体写法；代码结构见 `README.md` 的布局表。

## 1. 一次请求经过的层

一个下载请求依次经过五层，每层的输出是下一层的输入：

1. **缓存**（`objcache`）：按对象版本找回整块对象，或者声明没。
2. **条件判断**（`cond`）：看条件头，决定是终态（`304` / `412`）、忽略
   `Range`，还是继续。
3. **区间解析**（`rangehdr`）：把 `Range` 变成若干闭区间，或者声明整条忽略、
   不可满足。
4. **上游**：缓存没有整块对象时，向对象存储取回它。
5. **响应构造**（`respond`）：状态码、响应头、分段骨架，最后由 `Serve` 填入
   字节。

顺序很重要：条件判断先决定要不要继续，区间解析只在确定要返回内容之后才有意义，
而缓存读取不能把「已决定返回分段」这件事吞掉。

## 2. 客户端头 → 条件判断

`docs/conditional.md` 规定：

- ETag 与 Last-Modified 同时在场时，ETag 优先；出现了 ETag 条件头，时间头就
  不再参与判定。
- `If-Match` 用强比较，不命中是 `412`。
- `If-None-Match` 用弱比较，`GET`/`HEAD` 命中是 `304`（无 body），其它方法命中
  是 `412`。
- `If-Range` 只认强校验值；带 `W/` 的一律不匹配。不匹配时丢弃 `Range` 返回
  `200` 全量，而不是 `304` 或 `412`。
- 时间比较按完整时刻进行；HTTP-date 只到秒，但对象的最后修改时间可能带秒以下
  的部分，不能先把它截断再比。

条件判断的输出必须真的影响响应`304` 不带 body，`412` 不带对象 body，
`If-Range` 不匹配时不能进入分段分支。

## 3. 区间解析

`docs/range.md` 规定：

- 段数最多 4；超过就整条忽略并回 `200` 全量，不能只取前 4 段。
- 段内出现非数字、空段等情况，整条非法，回 `400`，不能跳过坏段继续使用好段。
- 起止倒挂、后缀为 0、起点不小于对象长度，都是不可满足，整条回 `416`，并带
  `Content-Range: bytes */<size>`。
- 终点超过对象长度时夹到 `size-1`；`first-` 取到末尾；后缀超过对象长度时起点取
  0。
- 归一之后每个区间都是闭区间，长度是 `end-start+1`。

不可满足与「忽略」是两件事：前者是 `416`，后者是 `200` 全量。

## 4. 缓存

`docs/cache.md` 规定：

- 键由租户、规范化路径、校验值三样组成，缺一不可，拼接不能有歧义。
- 只缓存完整的对象（上游 `200`）。
- 带 `Range` 的客户端请求对应的上游响应不写缓存，无论上游回 `200` 还是 `206`。
- 上游 `304` 只用来刷新元数据，不能把 `304` 或空 body 写成对象内容。
- 读取命中后拿到的是完整对象，分段由边缘自己裁；不能把整块对象当成分段 body
  发出去。

## 5. 响应造

`docs/response.md` 规定：

- `Content-Range` 两端都是闭区间：`bytes <first>-<last>/<size>`。
- 单段 `Content-Length` 等于区间长度。
- 多段响应用 `multipart/byteranges`，每个 part 自带 `Content-Range` 与
  `Content-Type`；整体 `Content-Length` 等于整段 multipart body 的字节数，不等于
  任何单段的长度。
- `Content-Disposition` 里文件名只能待在引号串或 `filename*` 里；引号、反斜杠要
  转义，CR/LF 等控制字符不得原样出现；非 ASCII 名字同时给出 ASCII 回退的
  `filename` 和 `UTF-8''` 百分号编码的 `filename*`。一个响应只允许一条
  `Content-Disposition`。
- `Accept-Ranges: bytes` 出现在所有可能返回分段的响应上，包括 `200`、`206` 与
  `416`。

## 6. 层与层之间的契约

- `Parse` 要能区分「没有 `Range`」「整条忽略」「不可满足」「有若干区间」四种
  结果；后两种必须让调用方走不同的分支。
- `Evaluate` 要能区分「继续」「`304`」「`412`」「忽略 `Range`」四种结果。
- `Build` 只负责状态码和头；字节由调用方按区间裁好填入。
- 缓存的键、写入门槛和读到的内容必须和上面三节一致，否则会出现跨租户命中、
  旧版本命中或分 body 污染全量条目。

任何一层把两种不同情况压成一种，都会在下一层变成可观察的错误：播放器跳转错位、
`Content-Length` 与 body 不符、或者把别的租户的对象发出去。
