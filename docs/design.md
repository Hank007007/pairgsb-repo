# 设计说明

本文说明 envseal 两条主链路「正确运行时应当发生什么」，作为实现与评审的共同依据。具体算法与代码结构不在此展开。

## 1. 职责边界

envseal 运行在 runner 上，与 job 一一对应地工作：

- 只接受本机连接（unix socket / named pipe）。
- 只负责一件事的两面：把 secret 交付给 job 的 shell，和不把 secret 交给日志前端。
- 不持有长期明文；env 文件是唯一的明文落盘点，并且有明确的生命周期。

## 2. 链路一：agent 申请 → 落文件 → 回收

### 2.1 申请与校验

agent 提交 job 标识、pipeline、branch、scope 列表和期望 ttl。sidecar 依次完成：

1. 找到该流水线的声明，确认请求的 scope 全部在声明范围内；任何一个越界，整份请求拒绝，不产生文件。
2. 用策略判断每个 scope 是否允许当前 pipeline / branch 取得；不允许的 scope 同样导致整份请求被拒绝。
3. 计算 lease 的有效期。效期由 job 声明的 `max_duration` 封顶，agent 上报的任何更大值都不被采纳。
4. 若该 job 已有仍然有效的 lease，直接复用：同一个 lease id、同一个文件路径、同一份内容、同一个到期时刻，不重新生成。
5. 否则创建一个新的 lease：生成标识、解析 secret、渲染文件、登记到期时间。

### 2.2 secret 解析

策略通过后，sidecar 从加密 store 取出所请求 scope 的记录并解密。store 中缺失的 secret 不是一个「空值」：它意味着这次申请无法完整满足，应当按拒绝处理，而不是把空串注入 env。

多个 scope 可能给出同名变量。合并时以策略声明的 scope 优先级为准，高优先级覆盖低优先级；遍历顺序和请求顺序都不影响最终取值。

scope 内部 secret 的名字同样要满足变量名规则（见 `docs/injection.md` §1.3）。

### 2.3 落盘

env 文件写到 leases 目录下。目录和文件的权限在内容出现之前就已确定：目录 `0700`、文件 `0600`。写入完成后文件内容即为该 job 的完整环境变量集合。

文件内容按 POSIX shell 可 `source` 的语法书写：任何值（包括含换行、空格、引号的值）在 source 之后都应与 store 中的原值逐字节一致。

### 2.4 读取

lease 的读取句柄只对持有者开放。读取返回文件内容。句柄的生命周期不得长于 lease 本身：lease 一旦撤销或到期，即使句柄在撤销前已经取得，之后的读取也必须失败。

### 2.5 回收

lease 到期或被撤销时，三件事必须一起发生：

1. 内存记录移除；
2. 读取句柄关闭；
3. env 文件从磁盘删除。

job 正常结束时由 runner 主动撤销 lease，效果与到期相同。未知 lease 的撤销是幂等的。

### 2.6 并发

同一 job 的并发申请必须收敛到同一个 lease。不同 job 的 lease 互不影响，文件路径不冲突。

## 3. 链路二：日志进入 → 掩码 → 输出

### 3.1 匹配集合

一次 job 的匹配集合来自它本次注入的全部 secret 值：所有被授予 scope 的值都参与匹配，包括由高优先级 scope 覆盖掉的值——被覆盖的取值同样曾是合法 secret，泄漏它一样有害。空串不参与匹配。

### 3.2 匹配语义

在连续的字节流上做最长匹配：同一位置有多个候选时选最长者。这保证一个 secret 是另一个 secret 前缀时，二者都能被完整替换，不会在输出里留下任何 secret 的后缀碎片。

### 3.3 流式处理

输入以任意大小的 chunk 到达，chunk 的切分位置与 secret 的边界无关。因此，无论 secret 被切在什么地方——同一 chunk 内、两个 chunk 之间、甚至跨三个以上 chunk——最终输出都必须把它完整替换为占位符。流结束时，尚未输出的尾部内容同样要经过掩码后送达，不能丢尾。

非 secret 字节必须原样通过，不改变编码，不丢控制字符。

### 3.4 与 lease 的关系

日志掩码使用的匹配集合应当与该 job 实际生效的 lease 一致。lease 尚未建立时，掩码器没有可用的匹配集合，此时日志按原样转发。

## 4. 错误与可观测性

错误响应只说明失败类别（未授权、scope 越界、store 缺失、lease 不存在等），不携带内部路径、secret 名称或 store 结构。日志可以记录更多细节，但同样不得写出 secret 明文。

## 5. 进程与配置

入口接受的配置项（socket 路径、leases 目录、策略文件、流水线声明目录、store 与密钥路径）在启动时一次性装配进服务。启动失败以非零码退出，正常运行期间不因为单个 job 的失败而退出。
