# 策略规范

策略决定一次构建能否取得特定 scope 下的 secret。策略文件由若干规则组成，每条规则包含 `effect`、`pipeline`、`branch`、`scope` 四个字段。

## §1 规则匹配

### §1.1 字段

- `effect`：`allow` 或 `deny`。
- `pipeline`：pipeline 名称的 glob。
- `branch`：分支名称的 glob。
- `scope`：scope 名称，精确匹配。

一条规则命中，当且仅当三个匹配字段全部匹配。

### §1.2 glob

`*` 匹配单个路径段内的任意字符序，不跨越 `/`。`**` 匹配任意字符序列，可以跨越 `/`。没有通配符时按字面量精确匹配。

## §2 结论

### §2.1 默认拒绝

没有任何 `allow` 规则命中时，结论为拒绝。

### §3 优先级

### §3.1 分支通配

`release/*` 只匹配 `release` 下的一层名称，例如 `release/1.0`、`release/hotfix`。它不匹配 `release/a/b`，也不匹配 `release/` 之外的路径。

### §3.2 deny 优先

只要有一条 `deny` 规则命中，结论就是拒绝，与命中顺序无关，也与后面是否还有 `allow` 规则无关。`deny` 规则写在 `allow` 之前还是之后，结论都必须相同。

## §4 scope

### §4.1 声明

流水线声明中列出该流水线允许申请的 scope。请求中的 scope 必须是声明集合的子集。

### §4.2 超集请求

请求包含任何一个未在流水线声明中出现的 scope 时，整份请求被拒绝。不得只注入已声明的部分，也不得为未声明的 scope 返回空值。拒绝时不生成 env 文件。

### §4.3 合并

多个 scope 同时被授予时，按 `docs/injection.md` §1.4 的优先级规则合并同名变量。

### §4.4 优先级声明

策略文件通过 `scopes` 数组声明每个 scope 的 `priority`，数值越大优先级越高。该声明是合并同名变量的唯一依据。
