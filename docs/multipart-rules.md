# multipart 解析层行为规范

本文规定 `formpost` 在解析一次 `multipart/form-data` 提交时**必须成立**的性质。
它是验收依据，不是实现说明：文档只描述可观察到的输入输出关系，不规定代码结构、
函数划分或算法。

术语：

- **请求体**：`Content-Type` 为 `multipart/form-data` 的那一段原始字节。
- **分界符**：`Content-Type` 的 `boundary` 参数所给的字符串。
- **部件**：请求体中被分界符框起来的一段，包含段头块、空行和段正文。
- **调用方**：本层的使用者，负责把解析结果交给入库处理器与对象存储。

---

## §1 成帧与分界符

§1.1 分隔行由 `CRLF--<boundary>` 构成：两个字节 `0x0D 0x0A`，紧跟两个连字符，
紧跟分界符本身。分隔行之后只允许出现 `CRLF`，或结束符 `--`。请求体起始处
（偏移 0）直接出现的 `--<boundary>` 视作隐含了一个前导 `CRLF`。

§1.2 分界符只有落在一个分隔行里才起分隔作用。段正文中出现与分界符相同的字节串、
但其前面不是 `CRLF`，或前面虽是 `CRLF` 但后面不构成完整分隔行的，**不构成分隔**，
必须原样留在该段正文中。

§1.3 因为 §1.2，段正文的字节数等于该段在原始请求体中两个真实分隔行之间的全部内容
（去掉紧邻分隔行的 CRLF 与最后一个 CRLF）。任何对段正文的字节计数都必须能在原始
请求体里按偏移复现；不允许因为正文里出现分界符字样而少算或多算。

§1.4 第一个分隔行之前的内容是前导区，结束行之后的内容是尾随区，两者都不产生部件，
必须被忽略。一个合法请求至少包含一对起始/结束分隔行。

§1.5 结束分隔行缺失、分隔行之间不满足 §1.1 的形状、或请求体根本不含分隔行时，
整次提交必须被拒绝并报告成帧错误；不得返回部分结果。

## §2 段头解析

§2.1 段头块由若干行组成，以 `CRLF` 分隔，以空行结束。每行的形状是
`名字: 值`，`名字` 是 ASCII token，大小写不敏感；值两侧的线性空白在解释时忽略，
但值内部的空白保留。

§2.2 参数化头部（如 `Content-Disposition`、`Content-Type`）按
RFC 2045 §5.1 解析：`主值 *( ";" 参数 )`。参数形如 `名字=值`，其中值可以是
token，也可以是双引号包围的 quoted-string。

§2.3 quoted-string 内的 `;` 是值的一部分，不是参数分隔符。
`filename="a;b.txt"` 必须解析出文件名 `a;b.txt`。

§2.4 quoted-string 内用反斜杠转义，RFC 2045 允许转义任意字符。
`filename="say \"hi\".txt"` 必须解析出文件名 `say "hi".txt`。
反斜杠不得残留在结果里。

§2.5 参数名大小写不敏感；同名参数出现多次时以第一次出现的为准。
无法按本条规定解析的参数使整次提交被拒绝，不得静默丢弃后继续。

## §3 文件名与处置参数

§3.1 部件的 `Content-Disposition` 必须是 `form-data`，并且带有 `name` 参数。
缺少 `name` 或处置类型不是 `form-data` 的部件使整次提交被拒绝。

§3.2 `name` 存在而没有任何文件名参数时，该部件是一个普通字段：报告其字段名与
解码后的正文。

§3.3 出现文件名参数时，该部件是一个附件，本层报告 `field_name`、`filename`、
`content_type` 和 `size` 四项元数据。`size` 是传输解码后正文的字节数（见 §4.3），
与对象存储里实际落盘的字节数一致。

§3.4 `filename*`（RFC 5987 / RFC 2231 编码参数）与 `filename` 同时出现时，
**一律以 `filename*` 为准**，`filename` 被忽略；`filename*` 的解码失败按 §5.5
拒绝整次提交，而不是回落到 `filename`。只出现 `filename*` 时同样以它为准。

§3.5 `filename*` 的形状是 `charset'language'percent-encoded-value`。
本层必须支持 `UTF-8`（大小写不敏感）。百分号编码按字节解码后再按字符集转换成
字符串；`%` 后不足两个十六进制位、或解码结果不是该字符集下的合法字节序列，
都算解码失败。

§3.6 报告出去的文件名中不得含有 `CR`（`0x0D`）、`LF`（`0x0A`）以及任何
`0x20` 以下的控制字符。构造出含这类字符的文件名（无论来自 `filename` 还是
`filename*`，无论是否经过百分号解码）都必须使整次提交被拒绝。

§3.7 拒绝错误里不得回显触发拒绝的原始文件名或任何控制字符。报文只说明拒绝原因
和出问题的头部名/段序号；调用方可以把这个报文写进日志与响应。

§3.8 §3.6 的检查针对最终要写进下载响应头的那个字符串。控制字符出现在
`filename` 里而 `filename*` 合法时，按 §3.4 以 `filename*` 为准，结果合法。

## §4 传输编码

§4.1 部件可以用 `Content-Transfer-Encoding` 声明正文编码。`7bit`、`8bit`、
`binary` 与缺省都表示正文按原样使用。

§4.2 `base64` 必须严格解码：正文（其中的 CRLF 与线性空白按 RFC 2045 被忽略）
必须由合法的 base64 字母表字符组成、长度满足补位规则。出现字母表以外的字符、
补位错误或尾部多余位时，整次提交被拒绝，不得得到截短的字节。

§4.3 `quoted-printable` 必须严格解码：`=` 之后只能是两个十六进制位，或紧跟
`CRLF` 的软换行。孤立的 `=`、`=` 后跟单个十六进制位、或 `=` 后跟非十六进制、
非 `CRLF` 的字符，都使整次提交被拒绝，不得把 `=` 原样留下或丢弃。

§4.4 声明了本层不支持的传输编码（如 `x-uuencode`）时，整次提交被拒绝。

§4.5 无论哪种情况，错误都必须从 `parse_multipart` 抛出，而不是返回部分解码的
正文或静默降级成 identity。

## §5 资源上限

以下四个上限是对请求体的硬边界，任何一处越界都必须在**发现越界的位置**立即中断，
不再继续解析后续内容，并抛出上限错误。

§5.1 `MAX_PARTS`：整次提交里所有层级的叶子部件总数上限。计数包含嵌套部件内部的
叶子部件；到达上限后继续出现的部件使提交被拒绝。

§5.2 `MAX_PART_BYTES`：单个叶子部件正文（分界后、传输解码前的字节数）的上限。

§5.3 `MAX_TOTAL_BYTES`：整请求体的上限。超过上限的请求体直接拒绝，无需先解析。

§5.4 `MAX_DEPTH`：嵌套层数上限。顶层部件是深度 1；一个 `multipart/mixed` 部件
内部再出现的部件是深度 2，以此类推。深度超过上限时拒绝，不得在越界层继续展开。

§5.5 上限值定义在 `formpost/limits.py`，本层解析时使用这些常量，而调用方也可能
在解析前用 `MAX_TOTAL_BYTES` 做入口校验；两处必须给出相同的判定。

§5.6 `multipart/mixed` 嵌套部件必须递归展开成叶子字段与附件。嵌套部件本身不产生
字段或附件记录，只贡献它内部的内容。嵌套的 `Content-Type` 缺少 `boundary` 参数时
整次提交被拒绝。

## §6 错误契约

§6.1 所有可预期的拒绝都以 `FormPostError` 的子类抛出，并带稳定的 `code` 属性，
便于调用方映射成 HTTP 状态码与工单。未知异常不应从本层逸出。

§6.2 被拒绝的提交不返回 `FormData`；解析是原子的，不会返回「前面若干段已经解析好」
的中间结果。

§6.3 报文是给运维看的元数据：可以包含字段名、段序号、头部名、触发的上限值，
但不得包含来自请求的头部值、文件名或正文片段。

§6.4 正常请求必须解析出与浏览器提交一致的段与附件记录；字段正文按 §4 解码后
以字节形式报告，字符集转换留给调用方。

## 附：对外接口

```python
from formpost import parse_multipart, FormPostError

data = parse_multipart(content_type, body)
data.fields       # tuple[Field(name, value)]
data.attachments  # tuple[Attachment(field_name, filename, content_type, size)]
```

错误类型：`MissingBoundaryError`、`MalformedBodyError`、`MalformedPartError`、
`MalformedHeaderError`、`UnsupportedContentTypeError`、
`UnsupportedTransferEncodingError`、`InvalidTransferEncodingError`、
`InvalidFilenameError`、`LimitExceededError`，均继承 `FormPostError`。
