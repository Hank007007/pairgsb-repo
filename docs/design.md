# scimfence 设计说明

本文说明 scimfence 的意图行为（intended behavior），作为 `docs/scim-profile.md` 与 `docs/attribute-authz.md` 的实现导读。本文只描述「应当怎样」，不描述「怎样实现」。

## 1. 分层

```
HTTP 层        路由、方法分派、查询参数、条件请求
  |
认证层          token 解析与校验，得到 {sub, tenant, scopes}
  |
授权层          租户绑定、属性级读写 scope
  |
SCIM 层         filter 解析/编译、PATCH 语义、序列化与裁剪
  |
仓储层          内存仓库，所有记录以 tenant 为一级键
```

依赖方向自上而下。SCIM 层与仓储层不读 HTTP 请求，只接收已校验的租户与参数。

## 2. 请求生命周期

一次请求按固定顺序经过以下检查，任一步失败即终止并返回对应状态：

1. **认证**：解析 `Authorization`，校验 token，失败 401。
2. **路由**：匹配 `/scim/v2/{tenant}/{resource}[/{id}]`，未知路径 404。
3. **户绑定**：路径 `tenant` 与 token `tenant` 不一致，403，且不触碰存储。
4. **参数解析**：filter、分页、投影、请求体语法；非法输入 400。
5. **资源定位**：`id` 只在 token 租户内查找，不存在或越界均 404。
6. **授权**：写操作按实际要写的属性逐个判定 scope；不足 403。
7. **执行**：读写存储；写操作成功后版本加一。
8. **序列化**：先按 scope 裁剪，再按投影收窄。

关键不变量：第 3 步之后，本次请求的租户只能来自身份对象；第 6 步必须在第 7 步之前完成；第 8 步的裁剪必须先于投影。

## 3. Filter 编译

### 3.1 语法树

解析器把 filter 文本转为独立的语法树，节点类型为：

- `and` / `or`：二元逻辑节点；
- `not`：一元逻辑节点；
- `cmp`：`{path, op, value}`；
- `pr`：`{path}`。

解析器只负责语法。它不得在解析阶段拼接或改写条件，也不得依赖正则对整个值区域做贪婪/非贪婪截取；字符串字面量按 §3.2 逐字符扫描，转义后的字符属于字面值。

### 3.2 编译

编译的目标是内部查询条件。正确的不变量是：

```
compiled = AND(tenantCondition, compileClient(ast))
```

`tenantCondition` 是独立的一层，不参与客户端 AST 的尔结构；无论客户端 AST 的顶层是 `and`、`or`、`not` 还是括号嵌套，租户条件都支配整个结果。实现上可以把它作为查询对象的固定字段，也可以在生成条件时始终用一次外层 `AND` 包裹，但绝不能把租户条件作为 AST 的一个叶子插入客户端表达式内部。

`co` / `sw` / `ew` 在编译为 LIKE 式条件时，必须先把字面值中的 `%`、`_`（以及转义符本身）转义，保证字面值只匹配自身；大小写处理在比较阶段完成。

### 3.3 执行

仓库对编译后的条件求值：先应用租户条件，再应用客户端条件。对 `not`，语义是「在本租户内、不满足子条件」。

## 4. PATCH

PATCH 的正确模型是「先定位、后授权判定、最后写入」：

1. 把每个 `path` 解析为「根属性 + 可选值过滤」的结构；
2. 在**当前资源**上只读地定位目标：
   - 根属性必须在 schema 中；
   - 子路径必须存在；
   - 值过滤必须命中现有元素；
   - 定位不到即 400，不得通过写入创建目标；
3. 以根属性为单位收集本次将要写入的属性集合；
4. 对集合中的每个属性判定写 scope，任一不足则 403，整个 PATCH 不落地；
5. 应用所有操作，成功后版本加一。

语义细节：

- `replace` / `remove` 是「修改已有」，目标不存在是错误；
- `add` 是「新增」，只能作用于已定义的属性，不能引入 schema 外的键；
- `remove` Group 的最后一个 member 后，Group 本身在本次操作内删除；
- 同一 PATCH 内多个 Operation 要么全部生效、要么全部不生效。

## 5. 序列化与投影

序列化对每个资源执行：

1. 构造完整资源视图；
2. 按 scope 删除无权读取的属性；
3. 应用 `attributes`（白名单）或 `excludedAttributes`（黑名单），`schemas`/`id`/`meta` 始终保留；
4. 输出。

第 2 步与第 3 步的先后顺序不可交换：投影只能在已裁剪的视图上收窄。任何查询参数都不能扩大可见属性集合。

## 6. 分页

`totalResults` 是过滤后（含租户约束）的**全量**计数，与 `count` 无关。`count` 只决定本页返回多少条，上限 100；`startIndex` 决定起始偏移。三者关系：

```
total   = matches.length
start   = startIndex (1-based)
page    = matches.slice(start - 1, start - 1 + min(count, 100))
itemsPerPage = page.length
```

不得用夹取前后的任一 `count` 值充当 `totalResults`。

## 7. 条件请求

`If-Match` 携带一个或多个实体标签。服务端解析标签（允许 `W/` 前缀，引号不计入内容），与当前 `meta.version` 做字符串比较。相等才写入；不等返回 412，且不修改资源、不递增版本。响应始终带 `ETag: "<version>"`。

## 8. 错误与原子性

所有错误按 scim-profile.md §7 的 SCIM Error 结构返回。写路径上的任何失败（语法、授权、条件不满足）都不得留下部分修改；实现应在校验与授权全部通过后才提交变更。

## 9. 测试策略

`test/` 下的用例覆盖正常路径：单租户、单 token、简单 `eq` filter、基本 CRUD、分页首屏。它们不代表全部规范；`docs/` 中的规范条款是验收依据。
