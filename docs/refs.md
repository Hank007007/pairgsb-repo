# refs.md — `$ref` 解析与环检测

## §1 本地片段

`$ref` 以 `#` 开头时指向本文档内部。片段用 JSON Pointer 表示：
`#/` 开头后跟以 `/` 分隔的 token，`~0` 表示 `~`，`~1` 表示 `/`。

## §2 远端引用

### §2.1 允许的 scheme

远端 `$ref` 只接受 `https:`。`http:`、`file:`、`ftp:` 以及其它任何 scheme
一律不认，整条请求在编译期失败。

### §2.2 允许的域名

远端 `$ref` 的主机名必须落在网关配置的域名白名单里，或白名单某一项的
子域。判定按 DNS 标签边界做：白名单项 `example.com` 接受
`a.example.com`、`b.a.example.com`，但不接受 `notexample.com`、
`example.com.evil.net`。白名单为空时远端引用一律拒绝。

### §2.3 抓取约束

- 单次抓取的响应体上限为 64 KB。超过上限时抓取失败，不截断后继续。
- 单次抓取必须有超时。超时按抓取失败处理，不能一直挂着。
- 抓取失败（网络错误、非 2xx、上限、超时）都必须让整条请求失败，
  并用失败的那一条 `$ref` 在提交 schema 中的位置指明是哪一条引用
  （见 dialect §4：不把远端 URL 回显到错误体里）。

### §2.4 远端文档的解析

抓回来的文档按 JSON 解析。它可以是完整 JSON Schema，也可以是一份只含
`$defs` 的字典。远端文档内部的相对 `$ref` 以该文档自己的基准地址解析，
且同样受 §2.1—§2.3 约束。

### §2.5 环检测的身份

环检测的身份是「**解析后的文档身份 + 解析后的片段**」，不是原始 `$ref`
字符串。下面三种写法指向同一位置时必须被视为同一节点：

```
#/a
#/a/
#/%61
```

原因是片段里的 token 要先做百分号解码，再做 JSON Pointer 反转义，
末尾多余的 `/` 不产生新的 token。远端文档的身份用其规范化后的绝对 URL
（去掉片段）表示。

一个节点正在解析栈上再次出现即为环。环不在第一次出现时立即报错，
而是展开到 `maxRefDepth` 这一层时以「引用深度超限」失败；这里说的
展开深度按**不同节点**计，不是按原始字符串计。

## §3 `$defs` / `definitions`

两者等价，`$defs` 优先。`$ref` 片段可以指到任意嵌套位置，不限于
`$defs` 下。

## §4 被拒绝的 scheme

`file:`、`ftp:`、`data:`、`javascript:` 等一律不认。本地文件系统不是
schema 的来源，网关进程不应该因为租户的 schema 去读本机文件。
