# limits.md — 硬性上限

这些上限与租户无关，网关在编译期与运行期都会用到。

## §1 请求体上限

请求体上限 `maxBodyBytes`（默认 1 MiB）是**在解析之前**量的。
网关必须按流式方式累计读到的字节，一旦超过上限立即停止读取并拒绝，
不能先把整个 body 读进内存、`JSON.parse` 之后再判断长度。

判断超限只看实际读到的字节数，与 `Content-Length` 头是否可信无关；
声明了正确的长度但流上实际更多，同样按超限处理。

## §2 正则长度

单条 `pattern` 的源码长度上限为 `maxPatternLength`（默认 512 字节）。
超过上限的 `pattern` 在编译期拒绝，不进入校验计划。

长度按 UTF-8 字节计，不是按字符计。

## §3 嵌套深度

实例的嵌套深度上限为 32。根实例深度记为 0，每进入一层对象属性或数组元素
深度加一。深度超过 32 时整条请求被拒绝，并且进程不能因为它而崩溃
（不能靠递归栈自然溢出）。

「嵌套深度」也包括 schema 自身的嵌套：编译时同样受 32 层限制，
避免租户用深到离谱的 schema 把编译期打挂。

## §4 编译缓存

编译缓存是**进程级共享**的，因此它的键必须完整描述影响编译结果的一切：
schema 内容、方言版本、租户身份。不同租户上传的相同 schema 不能互相命中
对方的编译结果；同一租户在方言升级后也不能命中旧结果。

缓存条目在命中时仍要经过全部编译期检查（正则长度与构造、`$ref` 白名单等），
缓存不能成为绕过检查的旁路。

## §5 正则构造

`pattern` 只允许正则引擎的常规子集。以下构造在编译期被拒绝：

- 回溯引用：`\1`—`\9`，以及 `\k<name>`
- 命名捕获：`(?<name>...)`
- 前后查找：`(?=...)`、`(?!...)`、`(?<=...)`、`(?<!...)`
- 原子组：`(?>...)`
- 递归 / 子程序调用：`(?R)`、`(?0)`、`(?&name)`
- 内联修饰符组：`(?i)`、`(?m)`、`(?s)` 这类单独成组的开关
- 字符类中的嵌套集合运算（`[\p{...}]` 除外，`\p{...}` 允许）

不允许的构造一律在编译期拒绝，并指明是哪一条 `pattern`。
