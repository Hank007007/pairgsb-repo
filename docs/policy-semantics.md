# verdictmesh 策略语义

本文件是 verdictmesh 的行为规范。接入方与引擎实现都以此为准；规范描述的是可观察行为，不约束内部实现。

## §1 请求与决策结果

一次决策请求包含四个字段：

| 字段 | 类型 | 说明 |
|---|---|---|
| `principal` | `string` | 发起方标识，使用路径式写法，例如 `/users/alice` |
| `resource` | `string` | 被访问资源，使用路径式写法，例如 `/docs/reports/q3` |
| `action` | `string` | 动作名，例如 `read`、`write`、`delete` |
| `context` | `object`（可省略） | 附属上下文，例如 `{ "role": "member", "clearance": 3 }` |

决策结果固定为三个字段：

| 字段 | 类型 | 说明 |
|---|---|---|
| `allow` | `boolean` | 是否放行 |
| `matchedPolicy` | `string \| null` | 生效规则的 `id`；没有任何规则生效时为 `null` |
| `reason` | `string` | 可供日志与排查使用的说明文本 |

`context` 省略时按空对象处理。`principal`、`resource`、`action` 缺失或不是非空字符串时，请求本身无效，应抛出错误而不是返回决策。

## §2 默认拒绝

规则集是白名单：只有当至少一条 `effect: "permit"` 的规则命中请求时，`allow` 才为 `true`。

- 没有任何规则命中：`allow: false`，`matchedPolicy: null`。
- 规则集为空同样适用于上一条。
- 命中仅有的规则是 `deny`：`allow: false`，`matchedPolicy` 为该 deny 规则的 `id`。

## §3 冲突消解：deny 优先

同一个请求可能同时命中多条规则。此时 `effect` 为 `deny` 的规则优先于 `permit`：

- 存在任意一条命中的 `deny` 规则时，结果为 `allow: false`，`matchedPolicy` 指向这条 `deny` 规则的 `id`。
- 不存在命中的 `deny` 规则、但至少有一条命中的 `permit` 规则时，结果为 `allow: true`，`matchedPolicy` 指向命中的 `permit` 规则。
- 多条 `deny` 同时命中时，取规则文件中声明位置最靠前的那条作为 `matchedPolicy`。
- 多条 `permit` 同时命中时，取声明位置最靠前的那条作为 `matchedPolicy`。
- 规则的声明顺序只影响 `matchedPolicy` 的选取，不影响 `allow` 的取值。

## §4 路径通配

`principal` 与 `resource` 的规则值都是路径模式，按 `/` 分段后逐段匹配

| 记号 | 含义 |
|---|---|
| 字面量 | 必须与对应分段完全相同 |
| `*` | 恰好匹配**一个**路径分段；不匹配零个分段，也不跨 `/` |
| `**` | 匹配**零个或多个**路径分段 |

补充约定：

- 模式与待匹配串都必须整体匹配，不是子串匹配。
- `/docs/*` 匹配 `/docs/a`、`/docs/b`，不匹配 `/docs`、`/docs/a/b`。
- `/docs/**` 匹配 `/docs`、`/docs/a`、`/docs/a/b`。
- 除 `/`、`*` 外的字符一律按字面量比较，`.`、`+`、`(`、`)` 等字符不具有正则含义。

## §5 资源回退匹配

请求中的 `resource` 会按 `/` **从细到粗**逐级回退，每条规则只要匹配其中任意一级即算资源命中。

对 `/a/b/c`，候选依次为：

1. `/a/b/c`
2. `/a/b`
3. `/a`

因此挂在 `/a` 上的规则对 `/a/b/c` 生效；挂在 `/a/b` 上的规则同样生效。回退不会越过根，根资源 `/` 的候选只有 `/` 本身。

规则一侧的通配模式与候选值逐级比较，`*` / `**` 的语义见 §4。

## §6 动作匹配

规则的 `action` 是字符串数组。请求的 `action` 与数组中的任意一项完全相等即算命中；不支持通配与大小写折叠。

一条规则在 `principal`、`resource`、`action`、`condition` 四项全部命中时，才算命中。

## §7 条件求值

`condition` 是以 context 键名为键的对象。每个值有两种写法：

- **标量**：等价于 `{ "eq": <标量> }`。
- **运算符对象**：可包含一个或多个运算符，必须全部成立。

支持的运算符：

| 运算符 | 语义 |
|---|---|
| `eq` | 相等 |
| `ne` | 不等 |
| `lt` | 小于 |
| `lte` | 小于等于 |
| `gt` | 大于 |
| `gte` | 大于等于 |
| `in` | 取值属于给定的非空数组 |

求值规则：

- **缺失键即不命中。** 条件引用的 context 键在请求中不存在时，这条规则的 `condition` 判为不命中，引擎正常继续匹配其他规则；不得抛错，不得把请求判为 500。
- **数值按数值比较。** 当两侧都是数值（或可解析为数值的字符串）时，`lt`/`lte`/`gt`/`gte` 按数值语义比较，例如 `10 > 9` 成立、`"10" > "9"` 按 `10 > 9` 处理。
- 字符串之间按字典序比较，布尔值按 `false < true` 比较。
- 两侧类型不可比（如对象、数组）时该运算符不成立。
- `eq`/`ne` 不区分数值与数值字串：`10` 与 `"10"` 视为相等。
- `in` 的右侧必须是数组；`in` 与 `eq` 一样采用宽松相等。
- `condition` 省略或为空对象时，条件判定为成立。
- 无法识别的运算符属于格式错误，在加载策略时拒绝，而不是在求值时静默忽略。

## §8 批量决策与缓存

`decideMany` 按数组顺序返回结果，第 `i` 个结果必须与对第 `i` 个请求单独调用 `decide` 完全一致，包括 `allow`、`matchedPolicy` 与 `reason` 的取值。

缓存是 `decide` 之上的可选优化，不得改变可观察结果：

- 缓存键必须覆盖所有会改变决策结果的请求输入：`principal`、`resource`、`action`、`context`。仅用其中一部分作键时，同一批中不同请求可能互相污染。
- 缓存命中与未命中的结果必须相同。
- 缓存条目有 TTL，过期后重新计算。
- 关闭缓存（`cache: false`）时，`decideMany` 与逐条调用 `decide` 结果一致。

## §9 格式错误

策略文件在加载时做一次性校验，校验失败抛出 `PolicyFormatError`（错误信息包含文件名与规则 `id`）。以下情形属于格式错误：

- 规则集不是数组，也不是含 `rules` 数组的对象。
- 规则缺少 `id` / `principal` / `resource`，或 `action` 为空数组。
- `effect` 不是 `permit` / `deny`。
- 条件使用了不支持的运算符，或 `in` 的右侧不是非空数组。
- 同一规则集内 `id` 重复。
- JSON 无法解析。
- 策略目录不存在。

运行期的请求错误（`principal` 等字段缺失、类型不对）抛出 `TypeError`，与策略格式错误区分开。
