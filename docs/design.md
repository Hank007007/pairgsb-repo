# rulelang 设计说明

本文说明 `rulelang` 的模块划分、编译流水线、错误模型和若干工程取舍。**语义的权威定义在
`docs/rule-syntax.md`**；本文只解释「系统应当如何组织」，不规定具体实现。

## 1. 目标与非目标

目标：

- 把运营写下的一行规则编译成可复用的表达式树，避免每个请求重复解析。
- 对不可信输入保持稳定：任何内容都不应导致进程崩溃、长时间占用或错误地「成功」。
- 编译与求值严格分离：编译失败的规则绝不进入求值。
- 错误信息对运营可读，带阶段与源串偏移。

非目标：

- 不做规则的多规则编排、优先级或动作模型（由网关上层负责）。
- 不做字段的类型推断或静态检查；字段的存在性与类型在求值时确定。
- 不提供规则持久化、版本管理。

## 2. 分层

```
源串 ──► lexer ──► parser ──► ast ──► eval ──► bool
          │          │
          └── limits ┘
```

- **lexer**：把源串切成 token。负责字符集校验、字符串解码、数字读取、CIDR 识别、源串与
  token 数量上限。
- **parser**：递归下降。负责优先级与结合性、括号配对、操作数位置约束（左侧必须是字段）、
  括号深度与节点数上限。
- **ast**：纯数据。节点不持有任何编译状态，可被缓存与复用。
- **eval**：接收 ast 与请求上下文，返回布尔或求值错误。不做任何解析。
- **compiler**：把 lexer 与 parser 串起来，作为对外的编译入口。
- **rlerr**：统一的诊断错误类型，携带阶段、偏移和消息。
- **limits**：集中定义资源上限，lexer 与 parser 共享。

分层的意义在于每一层的失败模式独立：词法错误不需要构造树，语法错误不需要上下文，求值
错误不污染编译结果。

## 3. 编译流水线

一次编译按固定顺序执行，每一步都可能提前终止：

1. **源串长度**：超过上限直接拒绝。这是最便宜的检查，放在最前面，避免为超长输入分配
   任何结构。
2. **词法**：逐个扫描字符生成 token。每生成一个 token 检查 token 总数上限。字符串与数字
   的合法性在此阶段判定。
3. **语法**：逐层下降构造 ast。进入左括号时递增深度，离开时递减，深度在每次进入时与
   上限比较。每新建一个节点递增节点计数。
4. **完成**：确认 token 流已耗尽且根节点是布尔表达式。

任何一步返回错误，编译即失败，调用方拿到 `nil` 树。编译器不返回「部分树」。

## 4. 优先级

规范要求的优先级层次是：

```
or  <  and  <  比较 / in  <  not  <  primary
```

编译结果必须如实反映这一层次：`a or b and c` 的根是 `or`，右子树是 `and`；`not a == b`
的根是 `not`，其子树是比较；括号显式覆盖层次。

优先级是**语法层的不变量**，与运算符在源串中出现的先后顺序无关。`a or b and c` 与
`a and b or c` 都应把 `and` 归到更紧的一层。

比较运算非结合：`a == b == c` 应当是语法错误，而不是嵌套的比较。

## 5. 括号深度

深括号是编译期最典型的资源风险：每层括号都使编译过程更深一层。深度上限必须**在括号被
打开的当下生效**：当前深度达到上限时，再进入一层就应返回错误；离开括号时深度回落。
合法的上限值必须能成功编译，上限加一必须被拒绝，错误位置应指向超限的那个左括号。

这与 token 数上限是两道独立的防线：token 上限限制总输入规模，深度上限限制单条嵌套链的
长度。仅有 token 上限时，一个远小于源串上限的输入仍可能具有极深的嵌套。

## 6. 字面量与转义

字符串转义表是封闭的：`\\`、`\"`、`\n`、`\t`。表中没有的转义字符是词法错误，而不是
原样保留；尾部孤立反斜杠同样是错误。

整数使用 int64。十进制数字序列转为数值后必须落在 int64 范围内；超出上界的字面量是
词法错误，不得以回绕后的负值或其他截断形式出现。

数字后紧跟标识符起始字符（例如 `1abc`）不是合法 token，应报错而不是切成两个 token。

## 7. 求值

求值是一个对 ast 的递归下降解释器：

- `and` / `or` 短路。短路不仅是性能优化，也是语义的一部分：右侧可能引用缺失字段。
- 比较要求两侧类型一致；排序比较只接受整数。
- `in` 有两种形态：右侧是 CIDR 时做网段判断，否则做等值判断。
- 字段缺失、类型不匹配、地址格式非法都返回求值错误。

**网段判断依据是网络前缀本身**，而不是地址文本的开头几个字符。`10.0.0.0/8` 覆盖
`10.7.7.7`，但不覆盖 `100.1.2.3`，尽管后者的文本也以 `10` 开头。判定结果只应由地址
落在哪个网段决定。

**边界输入**：`Eval` 必须能处理空树而返回错误，不能解引用。上层可能因缓存失效、配置
加载失败或调用方误用而传入空树；求值是面向每个请求的热路径，这里出错会让整个网关进程
受影响。

## 8. 错误模型

所有错误都是 `*rlerr.Error`：

```go
type Error struct {
    Stage Stage
    Pos   int
    Msg   string
}
```

- `Stage` 区分 lex / parse / limit / eval / config，便于监控面板按阶段聚合。
- `Pos` 是源串字节偏移，便于控制台高亮。
- `Msg` 面向运营，描述问题而非实现细节。

错误不携带内部堆栈；调用方不需要也不应该依赖具体错误文本做分支。上层若需要分类，应
使用 `Stage`。

## 9. 上限的取舍

四个上限分别防不同的攻击面：

| 上限 | 防的是 |
|---|---|
| 源串字节数 | 超大输入的内存与扫描时间 |
| token 数 | 超长表达式带来的解析与求值成本 |
| 括号深度 | 递归链耗尽栈 |
| 节点数 | 树规模与求值成本 |

它们不能互相替代。例如一个 100 字节的输入可以有 50 层括号，不会触发任何规模上限，但
会触发深度上限；反过来，一个极长的平铺 `a == 1 and a == 1 and ...` 不增加括号深度，只
由 token 与节点上限约束。

上限值定义在 `internal/limits`，词法器与语法器共享同一组常量，避免两处漂移。

## 10. 测试策略

- 现有测试覆盖单条比较、单个 `and`、括号、否定、成员判断、缺失字段与类型不匹配等正常
  路径。
- 测试通过公开入口（`compiler.Compile` 与 `eval.Eval`）驱动，不依赖内部函数。
- 错误路径的断言只检查「返回了错误」，不锁定错误文本，避免文案调整造成测试脆弱。

## 11. CLI

`cmd/rulelang` 提供三个子命令：

- `compile`：编译并打印缩进语法树及节点数。用于人工核对优先级与树形。
- `eval`：编译后对 JSON 上下文求值。上下文中的字段默认按字符串/整数映射，`-ip` 指定
  哪些字段按 IP 解释。
- `demo`：内置若干示例规则与上下文，直观展示优先级、否定、成员判断与转义的效果。

CLI 只依赖标准库的 `flag`、`encoding/json` 与 `os`，便于在网关镜像中直接构建。
