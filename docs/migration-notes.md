# Migration Notes — scimfence

记录 scimfence 自内部身份库前置以来的重要变更与事故。按时间倒序。

## 2026-02 — filter 短路导致跨租户批量导出

**影响范围**：租户 `acme` 的 3000 条用户记录被一个本应只看到自家 12 条记录的上游集成读取。

**经过**：该集成在同步任务中使用了一条组合 filter：

```
GET /scim/v2/acme/Users?filter=userName sw "svc-" or externalId pr
```

预期是「自己的服务账号」，实际返回了全部租户的用户。排查发现，编译层把调用方租户条件当作普通项拼接到客户端表达的顶层，当客户端表达式的顶层是一个 `or` 时，租户条件只落入其中一个分支，另一个分支不受约束。该集成随后把结果全量落到了自己的对账文件里，下游又同步进了数据仓库。

**后续要求**：租户条件必须支配整个客户端表达式（scim-profile.md §3.4），与客户端表达式是否为 `or`、是否带括号嵌套无关。回归用例需要覆盖 `or`、括号内 `or`、`not` 三类形态。

## 2026-01 — PATCH 的过滤路径未做属性级判定

**影响范围**：一个只有 profile 写权限的集成修改了 3 个用户的 `groups`。

**经过**：该集成使用 `PATCH` 携带 `path: "groups[value eq \"admins\"]"`。权限判定只看了 path 的字面前缀，认为它不是受控属性 `groups` 本身，从而放行。修复方向：带值过滤的路径以方括号前的根属性判定（attribute-authz.md §5.2）。

## 2025-12 — `co` 查询把用户输入当通配符

**影响范围**：按名字前缀搜索时返回了无关用户，上游据此合并了两个账号。

**经过**：filter 使用 `co`，右值中包含 `_`，被内部 LIKE 当作单字符通配符。要求：`co`/`sw`/`ew` 的字面值必须转义 LIKE 元字符（scim-profile.md §3.3）。

## 2025-11 — 引号转义破坏语法树

**影响范围**：一次批量创建因 `userName` 中含引号而失败，随后修复过程中发现 filter 可被构造成改变语义。

**经过**：字符串字面量解析未处理 `\"`，导致字面值提前结束，剩余内容被当作语法继续解析。要求：字符串解析遵循 JSON 转义（scim-profile.md §3.2），并拒绝尾随垃圾。

## 2025-10 — 投影参数绕过了 scope 裁剪

**影响范围**：无 `attr:groups:read` 的 token 通过 `?attributes=userName` 读到了 `groups`。

**经过**：投影与裁剪是两条独立代码路径，投影分支没有经过裁剪。要求：裁剪先于投影（attribute-authz.md §4）。

## 2025-09 — 分页计数不一致

**影响范围**：某同步任务在 `count=500` 时循环翻页，提前终止于第 2 页。

**经过**：服务端把 `count` 夹到上限，但 `totalResults` 沿用了夹取前的数值，客户端按此计算页数产生偏差。要求：`totalResults` 与实际切分自洽（scim-profile.md §5.2）。
