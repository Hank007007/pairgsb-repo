# tagwall 清洗规范

本文是 tagwall 的验收口径。它只描述清洗层「必须表现出什么行为」，不规定实现方式。
文中出现的「必须」「不得」「应当」均为强制要求。

---

## §1 范围与术语

tagwall 是工单系统评论内容的入库前清洗层。前端使用 `contenteditable` 编辑，
提交的是 HTML 片段；服务端在写库前调用 `tagwall.sanitize()`，返回值原样存库；
展示页面把存库的值直接赋给 `innerHTML`。

- **片段**：一段不保证良构（well-formed）的 HTML 内容，可以包含元素、文本、
  字符引用、注释与其它标记。
- **输出**：`sanitize()` 的返回值。它不是对输入的转义副本，而是一份重新书写的
  HTML 序列化结果。
- **存活元素**：输出中保留下来的元素。未列入标签白名单的元素一律不存活。
- **再清洗**：把输出再次交给 `sanitize()`。

## §2 输出不变式

1. 输出必须是良构片段：每个输出的开始标签都有与之配对的结束标签
   （空元素除外），属性值一律使用双引号包裹，属性值中的 `&`、`"`、`<` 必须写成
   `&amp;`、`&quot;`、`&lt;`。
2. 输出中的文本节点不得含有未转义的 `<`、`>` 与裸 `&`；它们必须以字符引用的
   形式出现。
3. **再清洗不变式**：对任意输入 `x`，必须满足

   ```
   sanitize(sanitize(x)) == sanitize(x)
   ```

   该等式对 §3–§7 中列出的每一类输入都成立。
4. 清洗不得依赖调用顺序、进程状态或随机性；相同输入必须得到相同输出。
5. 输入为空串时输出为空串。

## §3 标签策略

1. 只有 `tagwall.model.ALLOWED_TAGS` 中的元素名可以存活，元素名按 ASCII 不区分
   大小写比较。
2. 未列入白名单的**容器元素**必须连同其内容一起丢弃，例如 `script`、`style`、
   `iframe`、`object`、`embed`、`template`。
3. `VOID_TAGS` 中的元素（`br`、`hr`、`img`、`input`）没有结束标签；输出中不得为
   它们写出结束标签，也不得因为它们没有结束标签而认为输入不平衡。
4. 自闭合写法（`<br/>`、`<img ... />`）按对应的空元素处理；其它元素上的自闭合
   斜杠不改变其是否为容器元素的判断。
5. 元素的大小写、属性顺序和属性值引号风格不做保留要求，但输出的元素名必须为
   小写。

## §4 属性策略

1. 只有显式列入白名单的属性可以存活。白名单之外的名字一律丢弃，**不是**先排除
   少数危险名字、其余放行。
2. 事件处理器属性（`on*`）在任何元素上都不得存活。
3. 以下属性在任何元素上都不得存活，无论其元素是否在白名单内：

   - `formaction`、`action`、`srcdoc`、`xlink:href`、`xmlns`、`xmlns:*`
   - `data`、`dynsrc`、`lowsrc`、`srcset`、`ping`、`autofocus`
   - 任何以 `xlink:` 开头的属性

4. 同名属性重复出现时，只保留第一个。
5. 没有值的属性（布尔属性，如 `checked`）保留为无值形式。
6. 属性值的实体必须解码一次后再参与 §5、§6 的判定；输出时重新转义一次，保证
   再清洗不变式成立。
7. 属性名按 ASCII 不区分大小写比较，输出统一为小写。

## §5 URL 策略

适用于所有以 URL 为值的属性，包括 `href`、`src`、`cite`、`longdesc`、`poster`、
`background`、`formaction`、`xlink:href`。

1. 允许的 scheme 只有 `http`、`https`、`mailto`，按 ASCII 不区分大小写比较。
2. 没有 scheme 的相对引用（`/path`、`#frag`、`//host/path`）允许。
3. 其它 scheme（`javascript`、`data`、`vbscript`、`file`、`ftp` 等）一律拒绝，
   拒绝的属性整条丢弃，元素本身保留。
4. scheme 判定必须针对**实体解码后、去掉首尾空白后**的值进行。例如
   `&#106;avascript:`、`jav&#x61;script:`、`java&#9;script:` 解码后分别为
   `javascript:`、`javascript:`、`java<TAB>script:`，都必须被拒绝。
5. 属性值内部的控制字符与换行不得使一个非法 scheme 通过判定。

## §6 style 策略

1. `style` 属性只保留 `tagwall.model.STYLE_PROPERTIES` 中列出的声明，其余声明
   丢。
2. 每条声明的形式为 `property: value`（属性名与值之间允许空白），输出统一为
   `property: value` 形式，声明之间以 `; ` 连接。
3. 值中出现下面任一构造时，整条声明丢弃：

   - `url(`（无论括号内是什么 scheme）
   - `-moz-binding`，包括作为属性名或出现在值中
   - `expression(`

4. `-moz-binding` 这类厂商前缀属性不在白名单内，不得因为「前缀属性兼容旧浏览器」
   而放行。
5. 全部声明都被丢弃时，`style` 属性本身也不得出现在输出中。

## §7 注释、CDATA 与声明

1. 注释以 `<!--` 开始，以 `-->` 结束，整段丢弃，包括其中的内容。
2. `<!-->` 与 `<!--->` 是空注释，注释在 `>` 处结束；紧随其后的内容必须按正常
   规则继续解析。输入 `<!--><img src=x onerror=...>` 中，`<img ...>` 是普通元素，
   必须经过 §3、§4 的过滤，不得原样保留。
3. 未闭合的注释（找不到结束标记）一直延续到片段结尾；其后的内容视为注释内容。
4. `<![CDATA[` 至 `]]>` 之间的整段内容丢弃。
5. `<!DOCTYPE ...>`、`<?...?>` 等声明整段丢弃。

## §8 畸形标记与令牌化

1. 元素按出现顺序建立嵌套关系。结束标签必须与栈中最近的一个同名开始标签配对。
2. 结束标签无法与任何未闭合元素配对时，丢弃该结束标签本身，并**继续**按 §3–§7
   扫描后续内容。不得因为一次配对失败而终止扫描，也不得把剩余的源文本原样写入
   输出。
3. 配对成功时，被跨越的、仍处于打开状态的元素必须按嵌套顺序补写结束标签，保证
   输出良构。
4. 片段结束时仍未闭合的元素，必须在输出末尾按嵌套顺序补写结束标签。
5. 输入中的 `<` 如果不构成标签、注释或声明，必须作为文本处理并转义为 `&lt;`。
6. 标签名只由字母开头，随后可以出现字母、数字、`-`、`_`、`.`、`:`。

示例（用于说明 §8.2 的行为，不构成对实现的约束）：输入
`<svg></p><style><img src=x onerror=alert(1)></style>` 清洗后必须不包含任何
`style` 元素或 `img` 元素，把输出再次交给浏览器解析时不得产生新的元素。

## §9 其它

1. 文本中的 Unicode 字符（含中文、emoji）原样保留。
2. 已存在的字符引用按原文意义处理，不得二次转义（`&amp;` 输出仍为 `&amp;`）
3. 清洗器只依赖 Python 标准库。
