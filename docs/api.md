# HTTP API

keywaytransit 通过一个常驻进程为多个租户提供加密即服务。所有请求和响应均为 JSON，字符编码 UTF-8。

## §4.1 端点

| 方法 | 路径 | 用途 |
|---|---|---|
| POST | `/v1/encrypt` | 加密 |
| POST | `/v1/decrypt` | 解密 |
| POST | `/v1/batch` | 批量解密 |
| POST | `/v1/rewrap` | 重封装 |
| POST | `/v1/rotate` | 轮换 |
| POST | `/v1/destroy` | 销毁指定版本 |

所有端点都必须带有租户标识；租户由请求头给出，服务端不得信任请求体里的租户字段。租户标识缺失或非法时请求失败。

## §4.2 批量接口上限

`/v1/batch` 一次最多处理 **64** 条。

- 超过 64 条时，**整批拒绝**，不处理其中任何一条，也不返回任何部分结果。
- 条数为 0 时同样拒绝（没有可处理的内容）。
- 上限是硬上限，不能通过分批静默截断或只处理前 64 条来实现"不报错"。

## §4.3 错误响应

错误响应体只允许包含错误码以及与调用方输入直接相关的 key 名（如果需要指示是哪把 key 出错）。

- 不得出现异常文本、堆栈、traceback。
- 不得出现明文、明文长度、密文长度以外的内部统计。
- 不得出现密钥材料、内部文件路径、版本之外的实现细节。
- 不同的失败原因必须映射到各自稳定的错误码，至少区分：
  - 版本低于下限或已销毁：`key_version_gone`
  - 上下文不匹配：`context_mismatch`
  - 认证失败（头部被改、密文被改）：`decrypt_failed`
  - blob 无法解析：`invalid_blob`
  - 批量超限：`batch_too_large`
  - 请求非法：`invalid_request`

错误码取值是小写蛇形字符串。HTTP 状态码可以由实现按语义选择，但同一错误码在同类失败下必须稳定。

## §4.4 成功响应

成功响应返回 blob（base64 或十六进制，由实现定义并在文档中固定）或明文。响应中不得回显请求里的明文之外的内部信息。

## §4.5 审计

服务对每次加解密操作记录审计日志。

- 审计记录可以包含：时间、租户、key 名、操作类型、版本、结果码。
- 审计记录 **不得包含明文**，也不得包含未脱敏的请求体。
- 请求体中可能包含明文，审计不得整体转存请求体。
