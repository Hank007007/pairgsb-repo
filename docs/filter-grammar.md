# Filter DSL 语法与安全规范

状态：已冻结（安全评审 v1.2）
适用版本：filtergate-doc-query
规范编号：FG-SPEC-1

本规范定义前端 filter DSL 的语法、允许的算子、字段白名单、租户隔离口径、资源上限，以及网关在编译阶段必须产出的后端查询结构。后端 adapter 按本规范实现，网关必须先于 adapter 完成全部校验。

文中「必须」「不得」「应当」为强制要求；违反强制要求的 filter 一律在 `FilterGate.compile()` 阶段被拒绝，不得下发到 adapter。

---

## §1 范围

网关接收一段 JSON filter，完成以下工作后交给后端 adapter：

1. 结构校验与语法解析；
2. 算子白名单校验；
3. 字段白名单校验；
4. 嵌套深度与 `$in` 长度校验；
5. 标量类型校验与规范化；
6. 租户作用域注入；
7. 翻译为后端查询。

任意一步败，`compile()` 返回失败结果与 §8 规定的固定错误码，且 **不得调用后端 adapter**。

---

## §2 传输格式

- filter 是一个 JSON 对象（Python `dict`）。
- 根节点不得为空对象。
- 对象的所有 key 必须是字符串。
- 只允许 JSON 可表达的值：对象、数组、字符串、数字、布尔、`null`。网关不接受自定义对象或可调用对象。

---

## §3 顶层结构与逻辑算子

### §3.1 根节点

根节点是下列两种形态之一：

- **逻辑节点**：形如 `{"$and": [node, ...]}` 或 `{"$or": [node, ...]}`；
- **字段节点**：形如 `{"<field>": {"<op>": <value>, ...}, ...}`。

一个对象可以同时包含多个字段，也可以同时包含逻辑算子和字段；其语义等价于对所有成员取逻辑与。

### §3.2 逻辑算子

允许的逻辑算子仅有两个：

| 算子 | 操作数 | 语义 |
|---|---|---|
| `$and` | 非空数组，每个元素是合法节点 | 全部子节点同时成立 |
| `$or` | 非空数组，每个元素是合法节点 | 至少一个子节点成立 |

- 逻辑算子的操作数必须是数组；空数组不合法。
- 逻辑算子只能出现在节点层（根节点或逻辑节点的子节点），不得出现在字段值内部。
- 除 `$and`、`$or` 外，任何以 `$` 开头的 key 出现在节点层都属于未允许算子。

### §3.3 字段节点

字段节点的 key 是字段名，value 是一个非空对象，对象中的 key 是该字段上的算子。

- 字段值对象中的每个 key 必须以 `$` 开头。
- 字段值对象中的算子必须来自 §5 的允许集合；白名单之外的一切算子（包括 §5.6 的禁用算子）都必须被拒绝。
- 同一个字段可以同时出现多个比较算子（如 `$gte` 与 `$lt`），语义为逻辑与。

---

## §4 字段白名单

只有下列字段名可以出现在 filter 中。匹配是 **全名精确匹配**，大小写敏感：

| 字段 | 类型 | 说明 |
|---|---|---|
| `tenant_id` | string | 租户标识，保留字段，见 §6 |
| `level` | string | 日志级别 |
| `service` | string | 服务名 |
| `message` | string | 日志正文 |
| `host` | string | 主机名 |
| `trace_id` | string | 链路 ID |
| `status_code` | integer | HTTP 状态码 |
| `latency_ms` | integer | 延迟（毫秒） |
| `timestamp` | integer | Unix 毫秒时间戳 |

规则：

- 字段名必须与上表完全一致。
- **字段名中不得包含 `.`**。后端存储层把 `.` 解释为子文档路径分隔符；一旦放行，就可以越白名单读取任意子文档。含 `.` 的字段名一律拒绝。
- 字段名不得包含 `$` 或以 `$` 开头。
- 未列出的字段一律拒绝。

---

## §5 算子

### §5.1 比较算子

字段值对象中允许的比较算子：

| 算子 | 操作数 | 语义 |
|---|---|---|
| `$eq` | 标量 | 等于 |
| `$ne` | 标量 | 不等于 |
| `$gt` | 标量 | 大于 |
| `$gte` | 标量 | 大于等于 |
| `$lt` | 标量 | 小于 |
| `$lte` | 标量 | 小于等于 |

- 操作数必须是标量（字符串、数字、布尔或 `null` 中与字段类型相符者），不得是对象或数组。
- 比较的语义依赖字段类型，见 §5.5。

### §5.2 `$in`

```
{"<field>": {"$in": [v1, v2, ...]}}
```

- 操作数**必须是数组**。传入字符串、数字、对象、`null` 或布尔都视为类型错误。
- 数组必须非空。
- 数组长度上限见 §7。
- 数组元素必须是与字段类型相符的标量，不允许嵌套数组或对象。
- 所有元素必须与字段类型一致；不得对元素做隐式类型转换。

### §5.3 `$regex`

```
{"message": {"$regex": "<pattern>", "$options": "im"}}
```

- `$regex` 的值必须是字符串。
- `$regex` 的语义是 **字面子串匹配**，不是正则匹配。网关在翻译阶段必须把 pattern 中的正则元字符转义后再交给后端，避免用户输入被当作正则执行。
- pattern 长度上限见 §7；不得包含 NUL 字符。
- `$options` 可选；出现时必须是字符串，且只能由字符 `i` 与 `m` 组成，不得重复，顺序不限。其他字符（例如 `s`、`x`、`l`、`u`）都属于危险选项，必须拒绝。
- `$options` 只能与 `$regex` 同时出现；单独出现不合法。
- `$regex` 只能用于字符串字段。

### §5.4 禁用算子

下列算子无论出现在节点层还是字段值层，都必须被拒绝，错误码为 `UNKNOWN_OPERATOR`：

| 算子 | 原因 |
|---|---|
| `$where` | 允许执行脚本 |
| `$expr` | 允许服务端表达式求值 |
| `$function` | 允许执行自定义函数 |
| `$accumulator` | 允许执行自定义聚合函数 |
| `$text` | 全文检索，绕过字段白名单与资源上限 |
| `$jsonSchema` | 以 schema 形式注入任意查询逻辑 |

该列表不是穷举白名单的替代品：允许集合由 §3、§5.1–§5.3 正向定义，凡不在允许集合中的算子都必须拒绝。

### §5.5 类型规则

每个字段有固定类型（§4）。校验规则：

- 字符串字段只接受字符串。
- 整数字段只接受整数，**不接受数字字符串**，也不接受布尔值（Python 中 `bool` 是 `int` 的子类，实现时必须显式排除）。
- `null` 只允许用于 `$eq` / `$ne`。
- 不得把 `"100"` 与 `100` 视为同一种值进行比较，也不得为了「方便」把字符串强转成数字。
- 类型不符必须返回 `TYPE_MISMATCH`，不得静默转换、截断或跳过。

## §6 租户隔离

- 租户作用域由网关注入，来源是登录态中的租户标识，不得来自客户端 filter。
- `tenant_id` 是保留字段。用户 filter 中允许出现 `tenant_id` 条件，但网关**必须丢弃用户提供的租户条件**，并在查询根部注入唯一的 `tenant_id = <会话租户>`。
- 编译结果中出现的租户值必须与登录态一致；任何层级的用户输入都不得覆盖、追加或削弱该条件。
- 即使 filter 的其余部分非法，也不得在租户条件缺失的情况下调用 adapter。

---

## §7 资源上限

| 限制 | 值 | 说明 |
|---|---|---|
| 最大嵌套深度 | 32 | 根节点深度记为 1；每进入一层 `$and` / `$or` 深度加 1 |
| `$in` 数组最大长度 | 100 | 元素个数 |
| `$in` 数组最小长度 | 1 | 空数组不合法 |
| `$regex` pattern 最大长度 | 200 | 字符数 |
| 逻辑算子操作数最小长度 | 1 | 空 `$and` / `$or` 不合法 |

- 超过深度上限必须返回 `DEPTH_EXCEEDED`。校验必须在递归进入子节点之前完成，不得依赖 Python 调用栈兜底，也不得让超深输入触发 `RecursionError`。
- 超过 `$in` 长度上限必须返回 `LIST_TOO_LONG`。
- 上限判定发生在语法解析阶段，必须在调用 adapter 之前完成。

---

## §8 错误码

`compile()` 失败时返回下列固定错误码之一：

| 错误码 | 触发条件 |
|---|---|
| `INVALID_FILTER` | 根节点非对象或为空；字段值不是对象；`$and` / `$or` 操作数不是非空数组；字段值对象为空；出现非 `$` 开头的字段内 key；`$options` 单独出现 |
| `UNKNOWN_OPERATOR` | 节点层或字段值层出现不在允许集合中的算子，包括 §5.4 的全部禁用算子 |
| `FIELD_NOT_ALLOWED` | 字段不在 §4 白名单、含 `.`、含 `$` |
| `DEPTH_EXCEEDED` | 嵌套深度超过 §7 上限 |
| `LIST_TOO_LONG` | `$in` 数组超过 §7 上限 |
| `TYPE_MISMATCH` | 操作数类型与字段类型不符；`$in` 操作数不是数组；比较算子收到对象/数组；空 `$in` 数组 |
| `REGEX_INVALID` | `$regex` 值不是字符串、含 NUL、超过长度上限；`$options` 非法 |

错误码是公开契约：只允许新增，不允许删除、重命名或改变含义。

## §9 后端查询结构

adapter 接收网关校验后的规范化查询，并产出如下结构：

```json
{
  "collection": "log_events",
  "filter": { "op": "and", "clauses": [ ... ] }
}
```

### §9.1 逻辑节点

`{"op": "and", "clauses": [...]}` 或 `{"op": "or", "clauses": [...]}`。

### §9.2 叶子子句

| 算子 | 子句 |
|---|---|
| `$eq` / `$ne` / `$gt` / `$gte` / `$lt` / `$lte` | `{"op": "<name>", "field": "<field>", "value": <scalar>}` |
| `$in` | `{"op": "in", "field": "<field>", "values": [<scalar>, ...]}` |
| `$regex` | `{"op": "regex", "field": "<field>", "pattern": "<escaped>", "options": "<options>"}` |

`$regex` 的 `pattern` 必须是转义后的字面量；未提供 `$options` 时输出空字符串。

### §9.3 规范化

- 嵌套的 `$and` 必须被展平为同一层的 `clauses`。
- 同一 `and` 层级内的子句必须按规范化序列化结果排序，保证相同语义的 filter 产出稳定、可缓存的查询。
- 根层级的租户条件与其他条件处于同一个 `and` 层级。

---

## §10 编译前检查清单

网关在调用 adapter 之前必须逐条确认：

1. 结构合法（§2、§3）；
2. 所有算子均在正向白名单内（§3、§5），禁用算子已拒绝（§5.4）；
3. 所有字段均在白名单内且不含 `.`（§4）；
4. 深度与 `$in` 长度在上限内（§7）；
5. 类型校验通过，无隐式转换（§5.5）；
6. `$regex` pattern 与 `$options` 合法（§5.3）；
7. 租户条件已由网关注入，且用户输入无法覆盖（§6）；
8. 以上任一项失败时 adapter 调用次数为 0。
