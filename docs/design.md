# unpackfence 设计说明

本文说明解包层由哪些部分组成、各部分的职责边界，以及每一层应当满足的行为。
具体条款以 `docs/extract-policy.md` 为准；本文不展开实现细节。

## 1. 上下文

```
运营上传 ──▶ jobs/<job>/ 建立 ──▶ 解包 ──▶ jobs/<job>/in/ ──▶ 构建（不设防）
                                      ▲
                                  信任边界
```

解包是唯一检查外部输入的地方。构建阶段直接读取 `jobs/<job>/in/`，不再做路径、
类型或体积校验。因此解包层的每一项判断都必须是完备的：漏掉一条，构建阶段就会
在没有任何防护的情况下接触到根外内容。

## 2. 分层

| 层 | 职责 |
|---|---|
| `internal/archive` | 识别包格式，按顺序产出条目：名字、链接目标、类型、声明大小、条目体 |
| `internal/pathguard` | 把条目名映射为 job 根内的落点，拒绝不合规的名字 |
| `internal/quota` | 累计消耗，判断预算、压缩比与条目数 |
| `internal/extract` | 串联上述三层并真正读写文件系统 |
| `internal/fault` | 为每种拒绝提供独立的错误标识 |

分层的目的在于：判定逻辑集中、可单独核对，落盘逻辑只使用已经判定过的结果。

## 3. 流程

1. 建立 `jobs/<job>/in/`。
2. 打开包，识别 tar、tar.gz 或 zip。
3. 逐条目：
   a. 校验条目名；
   b. 计算落点并确认在 job 根内；
   c. 按条目类型处理：目录、普通文件、符号链接、硬链接、特殊类型；
   d. 记录消耗并检查预算、压缩比与条目数。
4. 任一检查失败即以对应的拒绝原因终止，返回给调用方。

## 4. 各环节的正确行为

### 4.1 条目名

名字是外部输入。需要识别的非法形态包括：绝对路径、Windows 盘符前缀、UNC 前缀、
以及任何经解析后越出根范围的相对路径。反斜杠与正斜杠等价处理，不能依赖运行平台。

判定必须以路径分段为单位，字符串前缀不足以说明两个路径的包含关系。

### 4.2 落点

落点由根与条目名合成，合成之后按路径语义解析，再判断结果是否位于根内。
仅当解析结果的每一个分段都在根内时才算合规。

### 4.3 符号链接

创建符号链接之前，需要确认其目标解析后仍在根内。链接近旁的目标按链接所在目录
解析。即便目标条目尚未出现，也不能放宽这条判断。

此外，条目名中间分段若已有符号链接，经由该链接落盘的位置同样要落在根内。

### 4.4 硬链接

硬链接的来源必须是根内已存在的条目，来源路径经过与普通条目相同的名字与范围判定。

### 4.5 条目类型

常规文件、目录、符号链接、硬链接可接受；设备文件、fifo、socket 及其它类型整体
拒绝。

### 4.6 体积

预算按实际写到磁盘上的字节累计，而不是包头声明值。压缩流可能比声明长，稀疏
条目也可能展开出远超声明的大小；这两种情况都必须体现在累计值里。

达到预算上限时立即停止，后续条目不再写。

### 4.7 压缩比与条目数

压缩比按已消费的压缩输入与已写出的字节之比观察，超过阈值即停止。条目数在每条
处理前计数，达到上限即停止。两条限制与体积预算是彼此独立的终止条件。

### 4.8 错误

每种拒绝对应独立的错误标识，错误信息带上条目名。调用方据此区分「名字非法」
「越界」「链接逃逸」「类型不支持」「超预算」「条目数超限」「压缩比超限」，
不能合并成一条笼统的失败。

## 5. 非目标

- 不负责构建阶段的行为。
- 不负责上传、鉴权与配额结算。
- 不负责包内容的语义正确性，只负责它落在哪里、占多少空间。
