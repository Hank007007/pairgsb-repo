# presign-spec — 签名 URL 规范

本文件是 `sigvault` 的规范性说明。文中「必须 / 不得」描述的是服务对外承诺的行为；
实现方式不在本文范围内。

## 1. 角色与流程

| 角色 | 说明 |
|---|---|
| 业务方 | 持有服务凭据（token + secret），调用签发接口换取签名 URL |
| 客户端 | 前端、移动端或第三方系统，只持有签名 URL，直接对存储读写 |
| 存储后端 | 本地目录，对象按 `<root>/<bucket>/<key>` 落盘 |

流程：

1. 业务方 `POST /presign`，用 `Authorization: Bearer <token>` 出示凭据，并在请求体里
   声明 bucket、key、目标方法、content-type、max-size、有效期。
2. 服务用该凭据对应的 secret 计算签名，返回一条自包含的 URL。
3. 客户端用这条 URL 直接 `GET` 或 `PUT` 对象；服务每次收到请求都必须重新计算签名并校验，
   不得信任 URL 里的任何字段。

## 2. 签名覆盖范围

签名**必须**覆盖下列全部输入，缺一不可：

| 输入 | 来源（签发时） | 来源（校验时） |
|---|---|---|
| 请求方法 | 业务方声明的目标方法，大写 | 实际 HTTP 方法，大写 |
| bucket | 请求体 | 请求路径的第一段 |
| key | 请求体 | 请求路径中 bucket 之后的余下部分 |
| content-type | 请求体；GET 固定为空串 | PUT 取 `Content-Type` 头（缺省 `application/octet-stream`）；GET 固定为空串 |
| max-size | 请求体；缺省为服务配额 | PUT 取 `max-size` 查询参数（缺省为服务配额）；GET 取服务配额 |
| 绝对过期时间 exp | 当前时间 + 有效期，十进制秒 | `exp` 查询参数 |

任何一项在签发与校验两侧取值不同，签名都必须不匹配。

## 3. 规范串

规范串按下列顺序、以单个 `\n` 连接：

```
sigvault-v1
<METHOD>
<bucket>
<key>
<content-type>
<max-size>
<exp>
```

约束：

- `<METHOD>` 为大写 ASCII。
- `<content-type>` 小写 ASCII；GET 为空串；不得带入参数（`;` 之后的内容）。
- `<max-size>` 与 `<exp>` 为十进制整数字面量。
- `<key>` 为对象 key 本身，不含前导 `/`。
- 规范串只由上述字段构成，不包含任何其他请求头、查询参数或主机名。

## 4. 签名算法

```
signature = HMAC-SHA256(secret, UTF-8(canonical_string))
```

以 64 位小写十六进制表示。校验时使用常量时间比较，不得以提前返回的方式逐字节比较。

## 5. URL 形式

```
/<bucket>/<key>?svc=<name>&exp=<epoch>&sig=<hex>[&max-size=<bytes>]
```

- `max-size` 只在签发 PUT 链接时出现；GET 链接不带该参数。
- URL 中的 `exp`、`max-size`、`svc`、`sig` **只用于重算签名**，其值不得直接作为
  校验通过的依据。改过任意一个参数，重算结果必须与 `sig` 不一致。
- key 中出现在 URL 上的百分号转义只用于传输；重算签名时使用解码后的 key。

## 6. 有效期

- `exp` 是绝对过期时间，UTC epoch 秒。
- `exp` 必须在规范串中，并且必须由签名保护。
- 缺失 `exp`、无法解析为整数、或当前时间 `>= exp` 的请求，都必须被拒绝。
- 服务端不得因为客户端未提供 `exp` 而把链接视为永不过期。
- 签发接口接受的有效期上限由服务配额决定（默认 3600 秒），超过上限的签发请求必须被拒绝。

## 7. key 授权

每个服务凭据带有一组授权前缀。key 必须落在其中某个前缀之下。

判断顺序是规范性的：

1. 先对 key 做百分号解码（`%2e` → `.`、`%2f` → `/` 等）。
2. 再做路径规范化：合并重复的 `/`、去掉 `.` 段、消解 `..` 段，得到规范化后的相对 key。
3. 最后用规范化后的 key 与授权前缀比较，且必须按路径段边界比较。

因此下列 key 都不得通过授权：

- `team-a/../team-b/x` —— 规范化后落在 `team-b/` 下；
- `team-a/%2e%2e%2fteam-b/x` 及其多级变体 —— 解码后同上；
- `team-a2/x` —— 与 `team-a` 是前缀兄弟目录，不在 `team-a/` 之下；
- 解码或规范化后以 `..` 开头、或以 `/` 开头、或为空的 key。

授权前缀本身是一个目录名，例如 `team-a` 表示 `team-a` 目录及其子目录；比较必须在路径段
边界上成立，`team-a2` 不属于 `team-a`。

## 8. 落盘路径

- 对象必须存储在配置的根目录之内。
- 由 bucket 与规范化 key 拼出的路径，其解析后的真实路径必须仍在根目录之内；
  软链、`..`、绝对路径、盘符、UNC 路径等任何把目标引出根目录的情形都必须被拒绝。
- 判断依据是文件系统解析后的真实路径（realpath），而不是字符串前缀。
- 越界必须报错且不得创建任何文件、目录或临时文件。

## 9. 上传大小

- PUT 的请求体不得超过该链接签名覆盖的 `max-size`。
- 超限时必须以 `413` 拒绝。
- 超限的上传不得在存储根目录下留下任何内容：不得留下临时文件、部分对象或占位文件。
- 未超限的上传原子地出现在最终位置，读取方不得看到半截对象。

## 10. HTTP 接口

| 方法与路径 | 用途 | 成功状态 |
|---|---|---|
| `POST /presign` | 签发链接 | `200`，响应体含 `url`、`method`、`expires_at`、`content_type`、`max_size` |
| `GET /<bucket>/<key>` | 下载对象 | `200`，响应体为对象字节 |
| `PUT /<bucket>/<key>` | 上传对象 | `201` |

失败语义：

| 情形 | 状态码 |
|---|---|
| 凭据缺失或无效 | `401` |
| 签名不匹配、过期、缺少 `exp` | `403` |
| key 不在授权前缀内 | `403` |
| 请求体超过 `max-size` | `413` |
| 路径越出存储根目录 | `400` |
| 对象不存在 | `404` |
| 请求体格式错误 | `400` |

错误响应体为 JSON 对象，至少含 `error` 字段。

## 11. 服务配置

服务通过 `--service NAME=SECRET:TOKEN:PREFIX[,PREFIX]:MAX_BYTES` 注册业务方，可重复。
`MAX_BYTES` 是该业务方单次上传的配额上限，签发时声明的 `max_size` 不得超过它。

## 12. 兼容性

`sigvault-v1` 规范串与 `sig` 的编码一旦发布即固定。任何新增字段都必须以新的前缀版本引入，
不得在 v1 上静默追加字段。
