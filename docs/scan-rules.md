# 扫描口径

本文件是 `credlint` 的行为规范。它描述"什么样的输入应当得到什么样的输出"，不描述实现。

## 1. 报告与脱敏

§1.1 报告里不得出现完整凭据。任何被命中的值在写出前都要打码，只保留前 4 个字符，其余字符以 `*` 取代；长度不超过 4 的值整体打码。

§1.2 打码同时适用于文本报告、JSON 报告的字段值，以及 `redact.redact_text`、`redact.redact_url` 的返回值。报告中的上下文片段、行号、路径可以保留。

§1.3 打码后不得能还原原值：报告输出中不允许出现长度超过 4 的原始凭据子串。

§1.4 `docs/design.md` 里描述的字段是报告对外契约的一部分。

## 2. 熵判定

§2.1 熵判定是规则命中之后的二次过滤，只对配置了 `entropy: true` 的规则生效。

§2.2 参与计算的是"取值本身"，不是整行。计算前须剥掉赋值左侧的变量名、分隔符（`:`、`=`）、包裹引号、以及行尾注释。

§2.3 长度不足 20 个字符的串不参与熵判定，视为不可靠样本，不得据此报告。

§2.4 随机性判定必须同时考虑字符分布与长度：长度越长，同样的阈值越容易达到。阈值不得脱离长度单独使用。

§2.5 形如 `AWS_SECRET_ACCESS_KEY="<40 位随机串>"` 的赋值必须命中；形如 `api_key = "<12 位随机串>"` 的短值不得命中。

§2.6 命中记录里可以附带熵值，便于安全同学排序。

## 3. 编码内容

§3.1 当一段内容整体看起来是 base64 编码时，解码一层后再用同一套规则扫描。

§3.2 标准 base64 与 URL-safe base64 都要识别；URL-safe 变体的字母表包含 `-` 与 `_`，可以没有 `=` 填充。

§3.3 只解一层。解码结果不是可读文本时不继续，也不要把二进制内容送进规则。

§3.4 解码后命中的记录必须标注来源，使报告能区分"原文命中"与"解码后命中"。

## 4. allowlist

§4.1 `.credlintignore` 每行一个模式；`#` 开头为注释，空行忽略。

§4.2 模式匹配的是相对于扫描根目录的整条路径，使用 `/` 作为分隔符。

§4.3 只有 `*` 是通配符，且只匹配一个路径段，不跨越 `/`。模式与路径按段一一对应：`vendor/*` 匹配 `vendor/key.pem`，不匹配 `vendor/a/key.pem`。

§4.4 没有通配符的模式按整条路径完全匹配。

§4.5 allowlist 只影响该路径下的文件，不影响同一批次里的其他文件。

## 5. 文件遍历

§5.1 跳过版本控制目录，至少包含 `.git/`。

§5.2 跳过依赖目录，至少包含 `node_modules/`。

§5.3 跳过二进制文件；判定依据可以是内容里的 NUL 字节，也可以是无法按文本解码。

§5.4 超过 2 MiB 的文件不读入内存，也不参与扫描。

§5.5 大小判定发生在读取之前；文件在判定阶段不应被完整读入。

§5.6 遍历顺序确定：目录与文件名排序后产出，便于复现报告。

## 6. URL 脱敏

§6.1 `redact_url` 对 URL 的 path 段中看起来像随机值的长串打码。

§6.2 query 中名字像凭据的参数（如 `token`、`key`、`secret`、`password`、`signature` 及其复合形式），其值也必须打码。

§6.3 非敏感的 query 参数、scheme、host、端口保持原样，保证日志可读。

§6.4 fragment 中若带有敏感参数，按 §6.2 同样处理。

## 7. diff 模式

§7.1 只扫描新增行；删除行与上下文行不产生命中。

§7.2 命中记录的行号是新文件中的行号，路径取自 `+++` 行且去掉 `b/` 前缀。

§7.3 删除文件（`+++ /dev/null`）不产生命中。
