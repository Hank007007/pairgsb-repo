# rulelang 规则语法

本文档定义边缘防护网关规则语言的**正确语法与求值语义**。它是编译器实现与运营文档共同遵守的规范；文中描述的是规则应当表现出的行为，不约束内部实现方式。

一条规则是一行文本，编译成语法树后对每个请求求值，结果为真即拦截或放行（由网关决定）。规则来源包括控制台手写、模板复制和批量导入，因此**任何输入都不得使编译流程崩溃**：非法输入必须以编译错误的形式结束。

---

## 1. 词法

规则源串由以下 token 组成。空白（空格、制表符、回车、换行）仅用于分隔 token，本身不产生 token。

| token | 形式 | 说明 |
|---|---|---|
| 标识符 | `[A-Za-z_][A-Za-z0-9_]*(\.[A-Za-z_][A-Za-z0-9_]*)*` | 字段名，可用点分段（如 `body.len`）。`and`、`or`、`not`、`in` 是保留字，不能用作字段名。 |
| 字符串 | `"..."` | 双引号包围，可含转义，见 §3。 |
| 整数 | `[0-9]+` | 十进制非负整数，语义类型为 int64，见 §3。 |
| 比较符 | `==`、`!=`、`<`、`<=`、`>`、`>=` | 六种，见 §2。 |
| 逻辑与 | `and` | 保留字。 |
| 逻辑或 | `or` | 保留字。 |
| 逻辑非 | `not` | 保留字。 |
| 成员判断 | `in` | 保留字。 |
| 左括号 | `(` | |
| 右括号 | `)` | |

标识符、保留字和数字之间必须有分隔。`andor` 是一个标识符而不是两个保留字。`1abc` 不构成合法 token。

源串中任何不属于上述形式的字符都产生词法错误，例如 `&`、`|`、`#`、单引号、单个 `=`、`!`（未跟 `=`）、`<` 后跟非 `=` 的字符本身仍是合法比较符 `<`。

token 记录其在源串中的起始字节偏移，用于错误定位。

## 2. 语法与优先级

### 2.1 表达式文法

规则顶层是一个逻辑表达式。

逻辑表达式由比较表达式通过 `and`、`or`、`not` 和括号组合而成：

```
expr        := orExpr
orExpr      := andExpr ( "or" andExpr )*
andExpr     := notExpr ( "and" notExpr )*
notExpr     := "not" notExpr | primary
primary     := "(" expr ")" | comparison
comparison  := operand cmpOp operand
operand     := ident | string | integer | cidr
cmpOp       := "==" | "!=" | "<" | "<=" | ">" | ">=" | "in"
```

`operand` 出现在比较左侧时必须是 `ident`；`cidr` 只允许出现在 `in` 的右侧（§2.3）。不存在只有 `operand` 而不带比较符的表达式：裸字段、裸字面量都不能构成规则。

### 2.2 优先级与结合性

从高到低：

1. `not`（一元，右结合）
2. `==`、`!=`、`<`、`<=`、`>`、`>=`、`in`（二元，非结合：不允许 `a == b == c` 这种链式比较）
3. `and`（左结合）
4. `or`（左结合）

因此：

- `a or b and c` 必须解析为 `a or (b and c)`。**`and` 的优先级严格高于 `or`，与书写顺序无关。**
- `a and b or c and d` 解析为 `(a and b) or (c and d)`。
- `a or b or c` 解析为 `(a or b) or c`。
- `not a == b` 解析为 `not (a == b)`：`not` 作用于其后的**整个比较表达式**，而不是先作用在左操作数上。
- `not not a` 解析为 `not (not a)`。
- `not a == b and c` 解析为 `(not (a == b)) and c`。
- `a in 10.0.0.0/8` 中 `in` 与比较符同级；左、右操作数都是 operand。

括号可以覆盖上述优先级。

比较运算本身不结合：`a == b == c` 是语法错误，而不是 `(a == b) == c`。

### 2.3 比较与成员判断的操作数

`comparison` 的左操作数必须是字段引用（标识符）；右操作数可以是字符串字面量、整数字面量或（仅 `in`）CIDR 字面量。

CIDR 字面量形如 `10.0.0.0/8`、`192.168.1.0/24`，只出现在 `in` 的右侧。其语法为四个点分十进制八位组加 `/` 加前缀度（0–32）。词法上，`in` 右侧的 CIDR 作为一个整体 token 处理；`in` 以外的位置出现的 `/` 是非法字符。

字面量出现在比较左侧（例如 `"x" == a`）在编译期报错，因为左侧必须是字段。

## 3. 字面量

### 3.1 字符串

字符串由双引号包围。支持的转义**只有**四种：

| 转义 | 含义 |
|---|---|
| `\\` | 反斜杠 |
| `\"` | 双引号 |
| `\n` | 换行（U+000A） |
| `\t` | 制表符（U+0009） |

除上述四种外，反斜杠后跟任何字符（包括 `\x41` 这类十六进制转义、`\r`、`\0`、`\/`）都是**词法错误**。反斜杠出现在字符串末尾而缺少被转义字符，同样是词法错误。

未转义的双引号结束字符串；字符串内部不得出现裸换行（未转义的 U+000A），出现即为词法错误。字符串没有长度以外的额外限制，但受 §6 的源串总长约束。

### 3.2 整数

整数字面量只接受十进制数字序列。其值必须落在 int64 范围内，即 `0` 到 `9223372036854775807`。

超出 int64 上界的数字序列（例如 `9223372036854775808`）是**词法错误**，不得回绕、截断为 `9223372036854775807` 或变成负数。前导零允许（`007` 等于 `7`）。规则语言只提供非负整数字面量。

### 3.3 布尔语义

表达式求值为布尔。比较表达式的结果是布尔；字段引用本身不能单独作为布尔表达式（`a and b` 中 `a`、`b` 必须是 `comparison`，而不是裸标识符）。因此 `src in 10.0.0.0/8`、`method == "POST"` 是合法比较，裸 `src` 不是合法规则。

## 4. 求值语义

求值时输入一个请求上下文，提供字段值。字段引用按名称查找。

### 4.1 字段取值

字段值有三种运行时类型：字符串、整数、IP 地址（点分十进制文本）。字段缺失时求值产生错误，而不是静默取零值。

### 4.2 比较

- `==`、`!=` 要求两侧类型一致：字符串对字符串、整数对整数。类型不一致是求值错误。
- `<`、`<=`、`>`、`>=` 只对整数有意义；对字符串或 IP 使用是求值错误。
- 字符串比较按字节序；整数比较按数值。

### 4.3 `in`

`in` 的语义是**成员判断**：

- 右侧是 CIDR 时，判断左侧字段值所表示的地址是否落在该网段内。判定依据是**网络前缀的二进制位**，而不是地址文本的开头几个字符。`10.0.0.0/8` 包含 `10.7.7.7`，但**不包含** `100.1.2.3`（后者的首个八位组是 100，不是 10）。
- 右侧不是 CIDR 时（字段对字段、字段对字符串字面量），`in` 判断左侧值是否等于右侧值。此形态只用于等值成员判断，不涉及网段。

### 4.4 短路

`and`、`or` 按布尔短路求值：`false and X` 不求值 `X`，`true or X` 不求值 `X`。短路可避免对缺失字段的无谓求值。

### 4.5 求值错误与 panic

求值过程中任何类型不匹配、字段缺失、地址格式非法都以求值错误返回，由调用方决定如何处理。求值**不得 panic**：包括对空树、nil 子节点、空字段名等边界输入。

## 5. 编译流程与错误

1. 检查源串长度（§6）。
2. 词法分析，检查 token 数（§6）。词法错误在此阶段报出。
3. 语法分析，检查括号深度与 AST 节点数（§6）。语法错误在此阶段报出。
4. 只有编译成功的规则才进入求值。编译失败的规则不得被求值。

所有错误携带阶段、源串字节偏移和消息。错误消息面向运营人员，应指出问题类型与位置。

## 6. 资源上限

为防止恶意或误导入的超大规则耗尽网关资源，编译过程受以下硬上限约束。任何一项超限都使编译以错误结束：

| 项 | 限 | 超出时 |
|---|---|---|
| 源串字节长度 | 8192 | 编译前即拒绝 |
| token 总数 | 2048 | 词法阶段拒绝 |
| 括号嵌套深度 | 64 | 语法阶段拒绝 |
| AST 节点总数 | 1024 | 语法阶段拒绝 |

括号深度指**未闭合左括号的最大数量**。第 65 个未闭合左括号必须被拒绝；深层输入必须在编译阶段到达上限时立即中止，不得依赖运行时栈耗尽来发现问题。合法的 64 层嵌套必须能编译成功。

AST 节点计数包含字段、字面量、比较、逻辑运算等所有节点。第 1025 个节点被拒绝。

上述上限在编译期检查，不得推迟到求值。

## 7. 示例

以下规则均为合法输入及其应得结果（`ctx` 为请求上下文）：

| 规则 | 结果 |
|---|---|
| `method == "POST"` | `method` 为 `POST` 时真 |
| `src in 10.0.0.0/8 and method == "POST" and body.len > 4096` | 三项同时满足时真 |
| `not a == b` | 等价于 `not (a == b)` |
| `a or b and c` | 等价于 `a or (b and c)` |
| `(a or b) and c` | 括号优先 |
| `path == "\\\""` | `path` 为 `\"` 时真 |

以下为非法输入：

| 规则 | 原因 |
|---|---|
| `a ==` | 缺少右操作数 |
| `a == b == c` | 链式比较 |
| `"x" == a` | 左侧不是字段 |
| `path == "C:\x41"` | 非法转义 `\x` |
| `path == "tail\"` | 字符串未闭合 |
| `n > 9223372036854775808` | 整数溢出 |
| `((((...` 超过 64 层 | 括号深度超限 |
| `a & b` | 非法字符 |
