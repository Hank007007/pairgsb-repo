# keyladder — 密钥策略

本文件是 `keyladder` 的行为规范。文中「必须 / 不得」是可被测试和审计的约束；实现方式不在本文件范围内。

一把密钥的字符串形态固定为：

```
kl_<env>_<id8>_<secret>
```

- `env`：签发时所属的环境段，取值为 `prod` / `staging` / `dev`
- `id8`：密钥的查找标识，十六进制小写字符串
- `secret`：不可预测的随机部分，只在签发响应中出现一次

调用方在调用 `verify` 时必须声明自己期望的环境（`env`）。

---

## §1 存储与摘要

1.1 持久化存储中，每条密钥记录只允许保存查找标识 `id8` 和由 `secret` 派生的摘要。
1.2 完整密钥串、`secret` 原文、以及任何可从中还原出 `secret` 的字段，都不得写入持久化存储、日志或错误信息。
1.3 摘要必须使用服务端持有的 pepper（进程外配置，不随数据文件分发）。没有 pepper 不得签发，也不得验证。
1.4 摘要比较必须针对完整摘要进行，不得把摘要截断成可枚举的前缀。
1.5 验证时由调用方出示的密钥串重新计算摘要，与记录中的摘要比对；比对通过只说明「这是该 `id8` 对应的那把密钥」，不构成放行结论。

## §2 环境绑定

2.1 `env` 段是密钥的组成部分。验证者必须确认「密钥串中的 `env`」与「记录中的 `env`」一致，且二者都必须等于调用方声明的 `env`。
2.2 任一不一致都必须导致拒绝，并以明确的 `reason` 返回，例如 `env_mismatch`。
2.3 环境不匹配属于拒绝，不属于告警。不得在给出告警后继续放行。
2.4 一次环境不匹配的验证尝试不得产生任何可用于后续放行的状态（包括缓存写入）。

## §3 轮换与宽限期

3.1 `rotate(id8)` 为新密钥生成新的 `id8`，新密钥继承原密钥的 `ownerId`、`scopes` 与 `env`。
3.2 轮换后，原记录必须记录 `rotatedAt`、`graceUntil` 和后继的 `successorId8`。
3.3 在 `now < graceUntil` 的区间内，原密钥与后继密钥都必须可用。
3.4 一旦 `now >= graceUntil`，原密钥必须立即不可用，不依赖任何后台任务或缓存过期；判定发生在每次验证时。
3.5 已过宽限期的原密钥被拒绝时，`reason` 必须明确分于「未知密钥」。
3.6 已被收回的密钥不得再被轮换；轮换已收回的密钥必须报错。

## §4 收回

4.1 `revoke(id8)` 必须在返回之前使该密钥的所有后续验证失败，与密钥是否曾在此前被验证过无关。
4.2 收回必须对同一进程内任何缓存副本生效。缓存中存在的旧副本不得在收回后继续参与放行判断。
4.3 重复收回同一把密钥必须幂等：返回成功语义、`status` 相同，并带上首次收回的 `revokedAt`，不得报错，不得刷新收回时间。
4.4 收回未知密钥必须返回「未找到」语义，不得创建记录。
4.5 收回之后重新签发的密钥属于新记录，不受旧记录的收回状态影响。

## §5 标识唯一性

5.1 `id8` 在实例内必须全局唯一，且签发前必须确认其尚未被占用。
5.2 若生成的 `id8` 已被占用，签发必须失败并返回明确错误，且不得修改、覆盖或删除已有记录。
5.3 「先写后查」不满足 5.1：判定必须在写入之前完成。
5.4 连续大量签发（数万次量级）之后，每条已签发密钥的记录都必须仍然存在且归属正确。
5.5 轮换生成的新 `id8` 同样受 5.1–5.4 约束。

## §6 时序安全

6.1 密钥查找与比较的耗时不得随「出示的密钥与真实密钥匹配长度」而变化。
6.2 不得在完整比较之前以长度差异提前返回；长度、前缀、后缀的匹配程度都不得外泄。
6.3 记录不存在与记录存在但摘要不符，对外表现必须一致（相同的 `reason`，可比的耗时）。
6.4 时序安全要求覆盖以下路径：格式解析之后、查找、摘要计算、摘要比较、收回与宽限期判定。

## §7 验证结果

7.1 `verify` 成功时返回归属与权限：`ok: true`、`id8`、`ownerId`、`scopes`、`env`。
7.2 失败时返回 `ok: false` 与 `reason`。可用的 `reason` 至少包括：
    - `invalid_format`：不满足 `kl_<env>_<id8>_<secret>` 形态
    - `unknown_key`：没有对应记录，或摘要不符
    - `revoked`：已被收回
    - `env_mismatch`：环境不一致
    - `grace_expired`：轮换宽限期已过
7.3 `reason` 必须是确定的、可被网关记录的字符串。不得用异常表示可预期的验证失败。
7.4 验证是只读操作；除了 §1 所述摘要计算与 §3 所述记录读取之外，不得修改记录状态。
7.5 网关可以根据缓存的验证结论短路请求，但 §4.2 与 §3.4 的判定必须每次生效。
