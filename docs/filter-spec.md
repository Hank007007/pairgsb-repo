# 过滤条件拼装规范

本文件规定 `filterweave` 对外承诺的行为口径。所有调用方（登录页查询、目录同步任务的增量拉取、
运维脚本）都以本文件为准；文档只描述“应当如何”，不约束内部结构。

文中“MUST / 必须”“MUST NOT / 禁止”为硬性条款，“SHOULD / 宜”为建议条款。
条款编号（§1、§2……）供评审与用例引用。

---

## §1 输入模型与适用边界

调用方以 `(属性, 操作符, 值)` 三元组描述一个条件，并提供组合方式（全部满足 / 任一满足）。
`filterweave` 负责把这组条件拼装成一段 LDAP 过滤串交给下层目录服务。

- §1.1 属性名与值都视为**不可信输入**。表单、同步 CSV、第三方推送都不得被假定已经清洗过。
- §1.2 拼装器是唯一的出口。调用方不得自行拼接片段后绕过拼装器交给目录服务。
- §1.3 拼装器不解释值里的语义（不做大小写折叠、不做去空格、不做解），只做转义与结构组装。
- §1.4 输入不合法时，拼装器必须抛错（见 §9），不得静默丢弃条件、不得把错误值替换成空串后继续。

## §2 属性名白名单

- §2.1 属性名只能取自 `docs/schema.md` 属性表中的第一列，判定时忽略大小写。
- §2.2 表中不存在的名称一律拒绝，包括但不限于：带 `*` 的名称、带空白的名称、空前后的名称、
  以属性名做前缀的推测性写法。目录服务没有“属性名前缀通配”这种能力。
- §2.3 校验必须发生在所有对外拼装入口上：单个条件、AND 组合、OR 组合、存在性条件，概无例外。
- §2.4 拒绝时的错误信息必须包含被拒的原始属性名，以便调用方定位是哪个字段出了问题。
- §2.5 属性名不参与转义；它要么原样来自白名单，要么被拒，不存在“转义后合法”的中间态。

## §3 值转义（`escape_value`）

- §3.1 下面五个字符在值中必须转义：

  | 字符 | 转义写法 |
  |---|---|
  | `\` | `\5c` |
  | `*` | `\2a` |
  | `(` | `\28` |
  | `)` | `\29` |
  | NUL (`U+0000`) | `\00` |

- §3.2 转义序列统一使用两位小写十六进制。
- §3.3 “按字节转”指：多字节字符按 UTF-8 编码后的字节序列处理§3.1 中的五个字符都是 ASCII，
  它们出现在多字节字符的 UTF-8 字节序列内部时**不构成**该字符，不得被拆分转义。
  换言之，转义判定以 Unicode 码位为单位，输出结果必须是合法 UTF-8 文本。
- §3.4 反斜杠必须先于其它字符处理，或采用等价的单遍扫描，保证 `\2a` 这样的输入不会在第二轮被
  二次转义成 `\5c2a` 以外的形态。最终结果中，任何来自输入的 `\` 都必须以 `\5c` 出现。
- §3.5 `escape_value` 只做转义，不做白名单、不做长度校验；这些职责在拼装层。
- §3.6 转义后的值再拼进 `attr=value` 时，必须整体落在 `attr=` 右侧，不得改变条件的边界。

## §4 通配符与存在性条件

- §4.1 值中的 `*` 是字面量，必须按 §3.1 转义成 `\2a`。
- §4.2 只有在调用方显式声明“此处需要通配”时，拼装器才可以输出未转义的 `*`。
  是否通配是调用方的显式意图，不能从值的形态推断（值里出现 `*` 不等于要求通配）。
- §4.3 存在性条件（present）的标准形式是 `(attr=*)`，其中 `*` 是协议语法的一部分，
  不是值的一部分。属性名同样要通过 §2 校验。
- §4.4 存在性条件不得接受“自定义值”参数；如果调用方传入了值该值必须不参与输出，
  或者调用被拒——两者择一，但绝不能把值拼进结果。
- §4.5 值中出现的 `*` 经过 §3 转义后，在解析侧必须仍然只匹配字面 `*`，不得被解释为通配。

## §5 布尔组合的结构

- §5.1 AND 条件输出 `(&(c1)(c2)...)`，OR 条件输出 `(|(c1)(c2)...)`。
- §5.2 每个子条件必须**自成一个括号组**。子条件在参与组合时不能被“裸拼”，
  即不允许出现 `(&(a=b)(c=d|e=f))` 这种一个子条件里混进多个同级条件的情形。
- §5.3 值的转义必须保证：无论值里出现 `&`、`|`、`!`、`(`、`)`、`\` 还是空白，
  解析出来的子条件个数与嵌套层级都必须和调用方给出的条件数、组合层级完全一致。
  条件数只能相等，不能多也不能少。
- §5.4 空集合的行为：`build_and([])` 与 `build_or([])` 必须给出一致的、可预期的结果
  （返回恒真/恒假过滤串，或抛错），并在设计说明中固定下来；不允许返回语法不完整的串。
- §5.5 组合可以嵌套；嵌套只能来自调用方显式给出的组合结构，不能由值的内容产生。

## §6 原始片段

- §6.1 禁止任何“把调用方提供的过滤片段原样拼入结果”的入口。
- §6.2 该限制是强制的：既有的原始片段路径要么物理上不可达（入口已移除），
  要么在拼装时被显式拒绝。二者都可接受，但不得保留一条“能用、但文档说别用”的通道。
- §6.3 任何测试都不得依赖原始片段通道来构造预期结果。

## §7 长度上限

- §7.1 过滤串总长度有上限，上限值由 `filterweave` 对外暴露的常量确定。
- §7.2 拼装完成（或拼装过程中可提前判定）时，如果结果长度超过上限，必须抛错（见 §9）。
- §7.3 禁止截断。截断会产生语义上仍然合法、但和调用方意图不同的过滤串，这比报错更危险。
- §7.4 长度按字符计，包含全部括号与操作符；多字节字符按其字符数计。

## §8 DN 值转义（`escape_dn_value`）

DN 的转义规则与 §3 的过滤值规则不同，不可互相复用。

- §8.1 出现在 DN 属性值中的下列字符必须转义：`,`、`+`、`"`、`\`、`<`、`>`、`;`、`=`。
- §8.2 值首尾的空格必须转义。
- §8.3 值首部的 `#` 必须转义。（中间的 `#` 不强制转义。）
- §8.4 转义写法为反斜杠加字符本身，例如 `,` → `\,`；反斜杠本身写成 `\\`。
- §8.5 拼装 `attr=value` 形式的 RDN 后，值里的分隔符不得增加 DN 的层级数。
  以 `=admin,ou=ops` 为例，结果必须仍是一个 RDN 的两个部分，而不是被解释成两级。
- §8.6 值为空串时，RDN 输出 `attr=`，不得因为“看起来不完整”而抛错或补字符。

## §9 错误约定

- §9.1 输入违反 §2、§6、§7 时，抛 `FilterWeaveError`（或其子类）。
- §9.2 错误信息必须可定位：属性名相关错误带属性名；长度相关错误带实际上限。
- §9.3 错误不得把未转义的原值整体回显到日志之外的对外响应中。

## §10 与调用方的关系

- §10.1 调用方只提供结构化输入，不提供字符串片段。
- §10.2 拼装器输出的是完整过滤串（最外层带括号），可直接作为 `search` 的 filter 参数。
- §10.3 属性表变更只通过修改 `docs/schema.md` 生效；拼装器不得内置一份影子白名单。
