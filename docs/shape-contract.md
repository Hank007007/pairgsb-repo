# Shape 契约（设计口径）

本文规定 `strictcast` 对外承诺的行为。它是规范，不是实现说明：任何实现都应当满足以下条款；条款没有要求的东西，实现可以自由选择。

## §1 术语

- **Shape**：一个接口注册的字段集合。每个字段有名字、`Kind`（`string` / `int` / `bool` / `string_list`）、是否必填、字节上限 `MaxBytes`、字符集类别 `Class`、可选枚举 `Enum`。
- **提交条目**：网关收到的一次键值对。JSON body 里是对象成员；form 里是 `map[string][]string` 的一个 key 及其值列表。条目保持提交顺序。
- **路径**：条目 key 解析后的位置，如 `owner.email`、`items[0]`、`items[]`。

## §2 解析与展开

### §2.1 路径语法

- 名字段由 `.` 分隔；下标段写成 `[n]`（`n` 为非负十进制整数）或 `[]`（通配列表）。
- 空 key、空名字段、未闭合的 `[`、非数字下标、负数下标都不是合法路径，必须拒绝。
- JSON body 的成员名与 form 的 key 使用同一套路径语法解析；因此 body 中字面成员名 `"a.b"` 与嵌套对象 `"a": {"b": ...}` 指向同一位置，二者同时出现构成冲突（见 §2.3）。

### §2.2 深度上限

- Shape 声明 `MaxDepth`，表示单个 key 允许的最大段数（名字段与下标段合计）。
- 段数超过 `MaxDepth` 的 key 必须被拒绝（错误码 `too_deep`），且该请求不得展开成任何树。

### §2.3 重复赋值与路径歧义

以下情况必须整体拒绝，错误码 `path_conflict`（或 `duplicate`，见下），错误里的 `path` 指向发生冲突的位置：

- 同一次提交里同一个位置被赋值两次（重复 key）。
- 一个位置同时被当作标量和容器：例如 `a` 与 `a.b` 同时出现，或 `items[0]` 与 `items[0].x` 同时出现。
- 展开过程中同一层名字段与下标段互相冲突（如 `a` 既要求是 map 又要求是 list）。
- 同一个列表既用显式下标 `[n]` 寻址，又用通配 `[]` 追加（例如 `items[0]` 与 `items[]` 同时出现）：两种寻址方式落在同一列表上即视为歧义，`path` 指向该列表名。

冲突必须以提交顺序无关的方式判定：先到的条目不能因为后到条目被静默覆盖，反之亦然；只要两次提交落在同一位置，就拒绝。**先拒后转**：结构问题在任何字段转换之前判定；出现结构问题不产生部分结果。

### §2.4 列表

- 一个列表只能选择一种寻址方式：要么全部用 `items[n]`，要么全部用 `items[]`。
- `items[]` 按提交顺序追加元素。
- `items[n]` 写入第 n 个位置；未填充的空位在最终结果里表现为空值，不得让下游看到越界空洞。
- 同一个 `[]` 通配 key 的多个值，按值列表顺序追加。

## §3 类型转换

### §3.1 整数 `CoerceInt`

- 只接受十进制整数字面量（可选前导 `+`/`-`），不接受空白、小数、进制前缀、千分位。
- 必须按**目标类型宽度**（当前为 `int32`）判断范围。超出 `[-2^31, 2^31-1]` 判失败，错误码 `out_of_range`；语法不合法错误码 `invalid_int`。
- 不得先按更宽的类型解析再静默窄化。

### §3.2 布尔 `CoerceBool`

- 只接受 `true` 与 `false` 两个字面量，大小写敏感。
- `1`、`0`、`t`、`f`、`yes`、`no`、`on`、`off`、`TRUE` 等一律判失败，错误码 `invalid_bool`。

### §3.3 字符串 `CoerceString`

- 先做 NFKC 归一化（§4.1），再对归一化后的值施加字节上限、字符集类别与枚举检查。
- 任一检查失败即拒绝；枚举比较针对归一化后的值。
- 空字符串在必填字段上视为「已提交」；是否允许空串由 `MaxBytes` 与 `Enum` 决定。

## §4 字符集与归一化 `CheckClass`

### §4.1 归一化时机

- 所有字符串在**任何**校验和长度判断之前先做 NFKC 归一化；校验的对象是归一化后的结果，返回值也是归一化后的结果。

### §4.2 类别

- `any`：不做字符限制。
- `text`：允许可打印 Unicode 文本，包括 CJK 与 emoji；拒绝控制字符与不可打印码位。
- `safe`：只允许 ASCII 字母、数字与 `-_.:@/ `；校验对象是归一化后的值。归一化会把全角等价写法折叠成 ASCII（如 `＜` → `<`、`＞` → `>`），而这些标点不在白名单内，因此必须拒绝。任何归一化后仍非 ASCII 的字符同样拒绝。

### §4.3 归一化后的长度

- 长度上限一律针对**归一化后**的值计算。归一化可能变长（如 `㍿` → 株式会社，1 字符变 4 字符），变长后超限必须拒绝，错误码 `too_long`。
- 校验与返回使用同一个归一化结果，不得先检查原文、再返回归一化值。

## §5 字节上限 `LimitBytes`

- `MaxBytes` 是 UTF-8 **编码后的字节数**上限，不是 rune 数、不是字符数。
- `MaxBytes <= 0` 表示不限。
- 超限必须拒绝（`too_long`）。**不得截断**：任何情况下都不能把值切短后继续使用，尤其不能按字节切出半个 UTF-8 序列。
- 对 `string_list`，上限逐元素计算。

## §6 错误载荷

- 400 响应体是 `{"errors":[{"path":...,"code":...}, ...]}`。
- 错对象只允许包含字段路径与稳定错误码；可以额外包含不含用户数据的说明，但**不得**回显用户提交的原值、归一化中间值、长度或其他可由原值推出的信息。
- 错误码集合固定：`missing`、`invalid_int`、`out_of_range`、`invalid_bool`、`invalid_charset`、`too_long`、`not_in_enum`、`invalid_value`、`bad_path`、`duplicate`、`path_conflict`、`too_deep`。
- 结构错误（§2）只返回一个错误，路径指向冲突/越界位置；字段错误可以一次返回多个，按路径稳定排序。

## §7 处理顺序

1. 解析每个 key 的路径，检查深度上限（§2.2）。
2. 展开成树，检测重复与歧义（§2.3）。
3. 对 Shape 中每个字段查值、转换（§3–§5）。
4. 汇总错误；有错时返回 400，无错时返回强类型结果。

第 1、2 步任一失败时，第 3 步不得执行。
