# 注入规范

## §1 env 文件

### §1.1 内容格式

env 文件是一组 `KEY=VALUE` 行，每行一个变量，行尾使用 `\n`。文件内容只包含已解析、已合并的变量，不包含注释。

### §1.2 权限

env 文件所在目录权限为 `0700`，文件限为 `0600`。权限必须在写入任何内容之前就位：文件从被创建的那一刻起就必须是 `0600`，目录从被创建的那一刻起就必须是 `0700`，不得先以宽松权限创建再收紧。

### §1.3 变量名

变量名必须匹配 `[A-Za-z_][A-Za-z0-9_]*`。任何不符合该规则的变量名都不得写入 env 文件，整份写入应当失败，而不是跳过该变量或把它原样拼进文件。

### §1.4 同名变量

不同 scope 可能给出同名变量。合并时以策略中声明的 scope 优先级为准：优先级高的 scope 覆盖优先级低的 scope，与 scope 的遍历顺序、请求中的排列顺序无关。优先级未声明的 scope 视为最低优先级。

## §2 值的转义

### §2.1 POSIX shell 单引号规则

值按 POSIX shell 的单引号规则写出，使得 job 执行 `source envfile` 后每个变量的值与 store 中的原值完全一致。规则如下：

- 用单引号包裹整个值；
- 值内部的每一个单引号写成 `'\''`（结束单引号、转义单引号、重新开始单引号）；
- 换行、空格、双引号、反斜杠、`$`、反引号等字符在单引号内保持字面值，不需要额外处理。

例如值 `a b\nc'd` 应写成：

```
KEY='a b
c'\''d'
```

### §2.2 空值

空值写成 `KEY=''`。

### §2.3 写入的原子性

env 文件的内容应当一次性完整写出。写入失败时不得留下半份文件。
