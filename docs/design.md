# design.md — 校验管线的正确行为

本文件描述 schemabind 在每一层「应该」做什么，作为实现与评审的共同口径。
具体关键字语义见 `dialect.md`，引用见 `refs.md`，归一见 `coercion.md`，
上限见 `limits.md`。本文件不给出实现方式。

## 1. 管线的四个阶段

一条请求依次经过：

1. **读取**：按流读取请求体，累计字节数并在超限时立即停止（limits §1）。
2. **编译**：把租户 schema 变成校验计划。编译是纯函数式的：
   输入（schema + 租户 + 方言 + 引用解析结果）相同则计划相同；
   schema 本身不被修改；任何违规在编译期拒绝，整条请求失败。
3. **归一**：把实例里的可无损转换的标量转成目标类型，写入缺省值。
   归一的产物是一份新实例（coercion §5）。
4. **校验**：对归一后的实例执行计划，收集结构化错误。

归一必须先于校验，缺省值参与校验。编译必须先于归一，因为目标类型来自计划。

## 2. 编译阶段的正确行为

- 计划只包含方言支持的关键字；未列出的关键字被忽略，不是错误。
- 每一条 `pattern` 都经过同一套策略检查：长度、禁用构造。
  这条检查对「首次编译」和「缓存命中」一视同仁（limits §4、§5）。
- 正则的缓存身份包含源码与 flag；不同 flag 的正则不是同一条正则。
- 计划缓存的身份包含 schema 内容、租户、方言版本。
- 编译深度受 `maxDepth` 约束；超过即拒绝，不依赖调用栈自然溢出。
- `$ref` 的解析结果参与计划，但 `$ref` 的解析本身受 refs.md 全部约束。

## 3. 引用解析阶段的正确行为

- 远端引用只接受 `https:`，主机必须命中白名单或白名单项的标签边界子域。
- 抓取有 64 KB 上限与超时；超限、超时、非 2xx 都是编译失败。
- 环检测的节点身份是「解析后的文档 + 解析后的片段」；同一位置的不同写法
  是同一节点。拥有多条指向同一节点的引用不是环（DAG 合法）。
- 真正的环展开到 `maxRefDepth` 时以「引用深度超限」失败，
  按不同节点计数。
- 引用失败的错误只说「哪一条 schema 位置的引用失败」，不回显远端地址。

## 4. 归一阶段的正确行为

- 只做 coercion §2 表里列出的转换；表外一律保持原样。
- 字符串到数字要求整串匹配十进制字面量且结果有限；不做前缀解析、
  不做十六进制、不剥离空白、不接受前导零。
- 布尔只认全小写 `"true"` / `"false"`；其余字符串保持字符串。
- 单值不自动包成数组。
- 归一写入新实例，调用方持有的对象不被修改；下游拿到的实例与
  校验时使用的不是同一引用。
- `default` 只写入 `properties` 声明过的字段，且写的是深拷贝。

## 5. 校验阶段的正确行为

- 对象字段判定顺序：`properties` → `patternProperties` → `additionalProperties`，
  命中即停（dialect §2）。
- `additionalProperties` 缺省视为 `false`（dialect §1.4）。
- 分支型关键字的失败错误指向分支内部实际出错的位置。
- 深度超过 `maxDepth` 时整条请求被拒，进程不受影响。
- 编译进计划的关键字都要被校验；没有实现的关键字不应静默通过。

## 6. 错误返回的正确行为

- 只返回结构化条目：`path`、`keyword`、`message`。
- 不返回实例原文、远端 URL、堆栈。
- 请求体超限、JSON 解析失败、schema 编译失败、实例校验失败
  是四类可区分的失败，各自有稳定的 `keyword`。

## 7. 不变式

- 同一 (schema, tenant, dialect, instance) 的校验结论与缓存状态无关。
- 校验失败时下游不会收到任何实例。
- 校验通过的实例可以被下游任意修改而不影响网关后续请求。
- 任何租户输入（schema、pattern、`$ref`、请求体）都不能让网关
  读本机文件、访问白名单外主机、或耗尽内存与调用栈。
