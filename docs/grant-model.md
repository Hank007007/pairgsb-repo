# Grant model

tenantmint 给内部文件服务发短期访问凭据。一个凭据回答三个问题：能访问哪个路径、能做哪些操作、什么时候作废。本文说明这些问题的判定口径；实现上的取舍不在这里展开。

## 1. 凭据的组成

一个凭据在签发时刻确定下列字段，签发之后这些字段不再变化：

| 字段 | 含义 |
|---|---|
| `id` | 凭据的唯一标识，撤回时按它定位 |
| `tenantId` | 凭据归属的租户 |
| `path` | 规范化之后的授权路径 |
| `actions` | 授权动作的集合 |
| `ttlMs` | 本次凭据的有效时长 |
| `issuedAtMs` | 签发时刻，由服务注入的时钟给出 |
| `expiresAtMs` | 作废时刻，等于 `issuedAtMs + ttlMs` |
| `revocationEpoch` | 签发时该租户的撤回合计数 |

凭据串是自包含的：校验方不再查询签发记录，只解串就能得到上述全部字段。凭据串的编码与解码属于传输层的约定，不在本文范围内。

## 2. 路径规范化与比

授权路径与请求路径必须换算成同一种形态之后才能比较。换算规则：

1. 反斜杠与正斜杠视为同一种分隔符。
2. 百分号编码的片段先解码，再参与后续处理。例如 `%2e%2e` 与 `..` 等价。
3. 空片段（连续斜杠）折叠。
4. `.` 片段消去。
5. `..` 片段消去其前一个普通片段；若前面没有可消去的片段则应判定为越界。
6. 绝对路径保持绝对形式，相对路径保持相对形式；相对路径按租户根解析之后再判定是否落在根下，规范化本身不改变绝对/相对这一点。
7. 结果必须落在签发凭据的租户根目录之下；不落在根下即拒绝签发或拒绝校验。

比较按**路径分段**进行，不按字符串前缀进行：`/tenant-a` 的凭据不能覆盖 `/tenant-ab/x`，`/tenant-a` 的凭据可以覆盖 `/tenant-a` 本身及其任意后代。路径末尾的 `/` 不构成差异。

规范化在签发和校验两侧都要做，两侧必须得到相同的形态；只有在两侧规则一致时，`/tenant-a/docs/../../tenant-b/secret` 与 `/tenant-a/docs/%2e%2e/%2e%2e/tenant-b/secret` 才会落到同一个被拒绝的形态。

## 3. 动作收窄

申请方给出的 `actions` 只是意愿，不是授权结果。真正写进凭据的动作集合是：

```
申请的动作集合  ∩  租户策略里管理员自己持有的动作集合
```

- 不在管理员动作集合里的动作不得出现，即申请方显式写了它。
- 申请方没有申请的动作不得凭空出现。
- 交集为空时，签发失败，不产生凭据。

校验时按**精确字符串**匹配动作名：只有与凭据中某个动作完全相同的请求才算命中，子串、前缀、大小写变体都不命中（凭据里写 `read` 时请求 `bread` 必须拒绝）。

## 4. 有效时长

有效时长受两个上界约束：

- 租户策略中的 `maxTtlMs`；
- 租户策略中的 `defaultTtlMs`（策略未给出时使用服务默认值）。

请求可以申请更短的时长，但不能超过任何一个上界。实际生效的时长取请求值与两个上界中的最小值，并且必须为正数。请求省略 `ttlMs` 时按默认值处理，同样受 `maxTtlMs` 约束。负值、`NaN`、`Infinity` 都不是合法请求。

## 5. 策略缺失

签发请求的租户必须在策略表中存在。策略缺失不是「没有任何限制」，而是无法判定权限：此时签发失败并返回可区分的错误（例如 `PolicyError`），不得回退到放行。同理，策略中缺少管理员动作集合或缺少根目录时，也不能按「空集合等价于无限制」处理。

## 6. 过期判定

过期判定必须使用凭据自身携带的时钟（`expiresAtMs`），与校验方注入的当前时刻比较：

- 当前时刻 `< expiresAtMs`：仍在有效期内。
- 当前时刻 `>= expiresAtMs`：已过期，拒绝。

边界归入过期一侧：请求恰好落在 `expiresAtMs` 时判定为过期。凭据中的 `issuedAtMs` 可以用于诊断，但不得替代 `expiresAtMs` 做判定。

## 7. 撤回

撤回以 `(tenantId, id)` 定位一个已发出的凭据。撤回发生后：

- 该凭据的下一次校验必须失败，且失败原因是撤回，而不是其他原因；
- 撤回记录必须持久化，进程重启后仍然有效；
- 撤回只影响被点名的那个凭据，同一租户在同一毫秒签发的另一个凭据不受影响；
- 撤回状态的查询口径统一走 store 导出的接口，撤销表不得成为只写不读的旁路。

凭据里记录 `revocationEpoch` 是为了让校验方能识别签发之后发生的整批撤回；单条撤回与整批撤回都必须在校验路径上生效。

## 8. 标识唯一性

凭据的 `id` 在签发时分配，且对「同一租户、同一毫秒、同一申请方」连续签发的两次凭据也必须不同。标识可以包含签发时刻，但时刻本身不构成足够的区分度；随机部分必须取自密码学安全的随机源，长度足以让穷举不可行。

## 9. 跨租户

校验时如果上下文给出了 `tenantId`，它必须与凭据内的 `tenantId` 一致；不一致按越权处理。路径落在租户根之外的情形同样按越权处理，无论该路径是通过 `..`、编码、重复斜杠还是符号链接形态绕进来的。

## 10. 失败结果的形状

`verify` 对任何拒绝都返回 `{ ok: false, reason }`，不抛异常；原因至少能区分：凭据格式错误、已过期、动作未授权、路径未授权、已撤回、租户不匹配。调用方据此决定 HTTP 状态码与日志级别。
